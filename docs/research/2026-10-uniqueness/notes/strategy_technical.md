# REMind: technical-differentiation strategy (state as of 2026-10-21, HEAD `88df221`)

Scope: eight prioritized engineering initiatives that would give `yuriy-mikityuk/remind-eeg` capabilities no other open-source project in the Muse / sleep-cueing space has, judged on technical differentiation only. Every proposal was checked against the checkout at `88df221` so that nothing already implemented is proposed again; where an initiative builds on existing code the "Extends" line names the modules. Corrections in the `verify_*.md` files override the original notes throughout (for example: κ 0.30 / precision 0.30 live only in PR #115 and issue #116, not in any repository file; the `p21` thresholds were *tuned on* one night, not validated; EazzZyLearn_pc is an open closed-loop TMR tool that does run on Muse; BOAS is CC0 and BIDS; Dream Recall is a REM-timed wake-up alarm). No efficacy of any kind (lucid dreaming, memory, clinical) is promised anywhere below; the repository's own `docs/validation.md` wording rules apply to every deliverable.

Source legend (all files in this folder): [RI] `repo_inventory.md`, [VRI] `verify_repo_inventory.md`, [CT] `cueing_tools_landscape.md`, [VCT] `verify_cueing_tools_landscape.md`, [ME] `muse_ecosystem.md`, [VME] `verify_muse_ecosystem.md`, [SS] `sleep_staging_tools.md`, [VSS] `verify_sleep_staging_tools.md`, [TS] `tmr_tlr_science.md`, [VTS] `verify_tmr_tlr_science.md`, [WR] `wearable_rem_physiology_open_science.md`, [VWR] `verify_wearable_rem_physiology_open_science.md`, [G1] `gap_1_direct_open_source_competitor_softcoding.md` (= `gap_eazzzylearn.md`), [G2] `gap_2_the_repo_s_only_accuracy_figures_live_so.md` (= `gap_github_validation_facts.md`), [G3] `gap_3_status_of_northwestern_interaxon_muse_tl.md` (= `gap_muse_rem_cueing_competitors.md`), [G4] `gap_4_the_ocular_channel_on_muse_why_the_eye_m.md` (pointer: `gap_ocular_channel.md`).

Effort scale: small = days to about a week of part-time work; medium = several weeks; large = months. "Data-bound" means the code is quick but the result needs new overnight recordings.

## 1. Where the repository actually stands

Facts the initiatives build on, with the corrections applied:

- The full chain (BLE source → recorder/replay → `EpochBuilder` → EEG/IMU/PPG features → heuristic REM detector / personal logistic classifier → `StableRemGate` → `ArousalGuard` → `TmrCueScheduler` → `AudioCuePlayer`) exists with 706 test functions, four CI jobs on Ubuntu/Python 3.11, 41 CLI commands, five pilot validators, a local web app, a Polar H10 companion recorder and a meditation side track [RI Q0–Q1, VRI A2/A4].
- The only real-sleep measurement is one EEG-only night (`overnight_20260707`, preset `p21`) replayed against GSSC; the gate thresholds 0.90/0.85 were fitted on that same night (in-sample), and "gate opens 342/959 epochs, κ 0.30, P 0.30 / R 0.80, p_rem ROC-AUC 0.758" exist only in PR #115 / issues #112/#116, never as a committed result file [VRI A6/C1, G2 Part A]. GSSC received AF7 as EEG and AF8 as pseudo-EOG, TP9/TP10 were never passed, GSSC 0.0.9 returns argmax only, and no publication evaluates GSSC on forehead-only EEG, so κ 0.30 is a consistency check between two unvalidated systems [G2 Part B].
- The heuristic detector is effectively one feature: `low_delta_power` AUC 0.776, `stillness` 0.53, `eye_movement_proxy` 0.500 (pinned at 1.0 on every real epoch), `theta_alpha_ratio` 0.42 (#116). The eye proxy is the unfiltered `mean|diff(AF7−AF8)|` scored against 0.05–0.20 µV per sample; real data gives 3.4–11.7 µV per sample dominated by high-frequency noise and the ~64 Hz optics line. The unit chain is correct (centered µV at 1450/16383 µV per count, identical to BrainFlow PRs #855/#856); the defect is feature design plus thresholds tuned on a synthetic 1 Hz sinusoid. The fix has not landed [G4 Part A; confirmed on `88df221`].
- `EpochBuilder` already has `stride_seconds` (default 30 s); the pilot runners still use 30 s epochs and the gate needs 60 s stable, so the first cue comes ≥60–90 s after REM onset [RI Q10, G2 A4].
- `ArousalGuard` works on 30 s feature rows (alpha 0.25/0.40, stillness 0.90, HR jump 10 bpm, artifact count) with `lower_volume_multiplier 0.50`, `pause 120 s`, stop after three pauses; there is no cue-locked (post-cue window) scoring and no up/down titration of a volume set-point. Volume is a 0–1 software gain (`max_volume 0.20`, calibration detectable ≤ identifiable ≤ comfortable), never dB SPL [RI Q4, VRI A9/A10].
- Randomization is item-level (seeded cued/uncued puzzles, uncued never schedulable); the morning retest is blind and next-morning only; the dream report is self-report (`lucid`, `cues_heard`, `confidence`, `dream_text`, `puzzle_incorporations`); there is no night-level sham arm, no delayed retest, no blind-rater coding and no N-of-1 statistics [RI Q4, confirmed by grep: no "sham" in `src/`/`docs/`].
- There is no EDF/BDF/BIDS/MNE export; `*.edf` is a forbidden pattern; feature rows export to CSV/Parquet only; MNE is used only inside the isolated stager scripts [VRI A13]. No PyPI package exists under any name; Python 3.8 is claimed but only 3.11 is tested [G2 A7, VRI B2].
- Real audio exists only through macOS `afplay`; on any other OS the `system` backend resolves to `dry-run` (no sound, logged); `caffeinate`, `say` and the `.app` launcher are macOS-only; CI never exercised the production audio path [RI Q10, VRI C2–C3].
- Optics (PPG/fNIRS) drain the battery (p1034 ≈23 %/h ≈4.3 h vs p21 ≈10 %/h), so nights record EEG+IMU only and the HR/HRV features are absent at night; optics also put a ~63.9 Hz line of up to ~40 µV on AF7/AF8 (#154). `ppg_features` computes peak-based HR (0.5–4 Hz band-pass), an RMSSD proxy and sudden-HR-change; the Polar H10 companion records ECG/RR/ACC with clock anchors; there is no Muse-optics-vs-Polar agreement analysis and the upstream `muse_fnirs_processor.py` is not used by `muse_tmr` [RI Q2/Q7, G2 A3; confirmed by grep].
- Repeated/lost BLE subpackets are now deduplicated (#160 → PR #182); the true EEG rate is ≈257.2 Hz [G2 A3f].
- Competitive position after corrections: an open NREM slow-oscillation TMR tool for Muse exists (EazzZyLearn_pc, OSC input, no REM logic, no safety or protocol tooling, last push 2025-11) and an open simulation-only NREM CLAS for Athena exists (Taran-Douley); open Muse overnight staging is offline YASA (southsko). No open project does REM-gated, arousal-guarded, randomized, replay-validated cueing on Muse; the vendor ships REM-timed waking (Dream Recall) and closed research TMR; the Paller lab's home trials use an unnamed wearable with no public code [G1, G3, VSS row 15, VME row 15].

### Initiative 1 — Replace the saturated eye-movement proxy with a low-passed bipolar AF7−AF8 REM-event feature

**Extends:** `src/muse_tmr/features/eeg_features._eye_movement_proxy`, the weights/thresholds in `src/muse_tmr/models/heuristic_rem_detector.py`, fixtures in `tests/test_eeg_features.py` and `tests/test_rem_detector.py`; implements the owner's own #116 roadmap (zero → redesign → refit → re-grid) and the AF7−AF8 point raised in #167.

**Build (issue-ready):**
1. Zero the `eye_movement_proxy` weight on `main` now (0.25 → 0, renormalise the remaining weights) in its own PR, so the gate behaviour change is traceable before any new feature lands (#116 says 0.40 of weight goes to a dead feature and an anti-signal).
2. New `_rem_event_features(AF7, AF8)`: bipolar difference; band-pass ≈0.3–5 Hz; when an optics preset is active, remove the ≈63.9 Hz line first (the PR #155 filter runs only before the complexity metrics); detect deflections by duration (≈0.3–1.5 s) and a *per-night robust amplitude threshold* (k × MAD of the filtered difference), not the 50–325 µV EOG constants of `yasa.rem_detect`, which assume a true EOG derivation; emit `rem_event_count`, `rem_density_per_min`, `last_rem_event_age_s`, `rem_burst_active`, plus event timestamps (consumed by Initiatives 5 and 6).
3. Fixtures that would have caught the current defect: biphasic opposite-polarity deflections of 20–60 µV on 1/f noise of 10–20 µV RMS with a 40 µV 64 Hz line; assert the old proxy saturates (score 1.0) and the new feature does not (min ≠ max over epochs); keep the committed 28 KB raw fixture as a replay regression.
4. Refit: run the per-feature AUC analysis of #116 through `scripts/validate_rem_detection.py` on ≥2 REM-bearing nights (GSSC reference), commit the metrics table (numbers only) to `docs/`, then refit `eye_movement_proxy_min/strong` (or percentile-normalise per night) and re-grid gate thresholds per preset.
5. Acceptance: non-degenerate feature distribution on real nights, AUC against reference REM > 0.5 and reported, Pilot 3 still shows zero uncued `play`, `docs/data_model.md` updated.

**Evidence:** [G4 A] the saturation is a feature/threshold defect, not units (every link is centered µV; `diff()` weights 64 Hz ≈64× more than a 1 Hz eye movement; owner measured 3.4–11.7 µV/sample raw vs 0.09–0.35 after a 5 Hz low-pass). [G2 A2] the #116 AUC table (0.776 / 0.53 / 0.500 / 0.42). [WR KQ3, VWR row 6] Esfahani et al. 2023 (bioRxiv, 135 ZMax+PSG nights): REM events detected on ZMax F7−F8 vs PSG horizontal EOG, counts r = 0.66, density r = 0.60, ≈1.8× over-count, attenuation attributed to the nearby Fpz reference; durations/speeds did not correlate. [WR KQ1] Lanthier et al. 2025: eye blinks are visible in Muse frontal channels (used to align Muse with PSG). [G4 B] Raduga et al. 2023: pre-agreed eye movements distinguishable at a single Fpz electrode in 7/8 lucid dreams; 154 LRLR signals scored on two frontal ZMax channels. [SS KQ3] frontal scorers call REM early; sequence constraints are the recommended fix.

**Why no open project has it:** Dreamento calls `yasa.rem_detect` only in its BrainProducts PSG branch with EOG indices and only offline; the ZMax branches never do [G4 B1]. ezscore-f outputs stages, not REM events [SS KQ2]. EazzZyLearn_pc receives a REM probability over OSC and never acts on it; it has no ocular feature [G1 §2]. Taran-Douley uses "eye-movement vetoes" only to stay out of REM [ME Q3]. INSPEC/Lucid Scribe detect eye movement by camera [CT]. No Muse project exposes a REM-density feature.

**Effort:** small for steps 1–3 (one feature function, ≈200 lines plus tests); data-bound for steps 4–5, which need at least two new REM nights with a reference (the 2026-07-07 recording is not on the owner's machine, #116).

**Risk / caveat:** AF7/AF8 referenced near Fpz attenuate horizontal EOG, and the ZMax analogue over-counted ≈1.8× [VWR G]; blinks (wake/N1) and frontal slow waves (N3) share the band, so this remains a *supporting* feature in a conjunction, never a trigger; the only available reference (GSSC fed AF7 + AF8-as-EOG) is itself unvalidated on forehead EEG [G2 B], so gains must be reported as AUC against an automated proxy, not as REM accuracy.

### Initiative 2 — A causal, benchmark-validated frontal REM detector with an open validation protocol (BOAS transfer → Muse anchor nights) and a 5–10 s hop

**Extends:** `src/muse_tmr/models/ml_rem_detector.py` (today a logistic layer on the heuristic's own sub-scores, so a recalibration rather than an independent model [RI Q3]), `scripts/validate_rem_detection.py` (accepts only `raw_amused.bin`; reference via YASA/GSSC subprocess), `src/muse_tmr/features/epochs.EpochBuilder.stride_seconds` (exists, unused by pilots), `src/muse_tmr/annotations/`.

**Build (issue-ready):**
1. `data/bids_headband_source.py` (or a converter): read BOAS `*_acq-headband_eeg.edf` (HB_1/HB_2 ≈ AF7/AF8 at 256 Hz, six IMU channels, `HB_PULSE`) and the `stage_hum` consensus into `MuseFrame`/epoch rows so every existing feature extractor runs unchanged; TP9/TP10 marked missing (missing modalities are normal by design).
2. A feature-level classifier trained on BOAS from the repo's EEG+IMU(+PPG) features plus Initiative 1's REM-event features; strictly causal (past context only, e.g. the last 5–10 min of rows); subject-level train/val/test split; class-balanced; an artifact class as in ezscore-f; saved in the existing versioned artifact JSON. Optionally a raw-waveform model for comparison, but the feature-level model is the one that stays replay-testable and explainable (reason codes).
3. Harness v2: `validate_rem_detection.py --labels <edf+ hypnogram | events.tsv>` to score against external labels; add REM-onset detection latency (first reference-REM epoch → first gate-open), per-REM-period recall, false-positive REM minutes per night; log the exact `--eeg/--eog` invocation into the metrics JSON (never logged for #115 [G2 gap]); commit a JSON schema.
4. Hop: wire `stride_seconds = 5–10` into the Pilot 3/4 runners behind a flag; make `StableRemGate.min_stable_seconds` count wall time rather than epochs; measure first-cue latency in replay and publish the latency budget.
5. Fine-tune path: `train-rem-classifier --init <boas_artifact>` with the user's `annotate-template` rows or imported hypnograms (Initiative 4) as fine-tuning data; leave-one-recording-out already exists.
6. Publish `docs/validation_results.md`: BOAS subject-level REM κ/F1/precision at the operating point and onset latency; add Muse anchor-night numbers once ≥1 expert- or device-scored Muse night exists; until then the detector is "transfer-validated", not "Muse-validated".

**Evidence:** [VSS row 14, VWR row 12] BOAS: CC0, BIDS, 128 nights from 100 people, Ikon headband AF7/AF8 at 256 Hz + IMU + PPG with simultaneous Micromed PSG scored by three experts with a fourth tie-breaker, ≈36 GB, OpenNeuro ds005555. [SS KQ4] fine-tuning/personalisation gains: U-Sleep κ 0.57 → 0.71 on ZMax, ear-EEG 70.1 → 73.7 %, self-supervised learning on BOAS >80 % with 5–10 % of labels; "no turnkey fine-tune-on-my-nights tool" exists. [SS KQ1/KQ3, VSS A–B] PSG-trained generic stagers collapse on forehead EEG (YASA κ 0.40–0.45 and REM recall 0.62 on home ZMax; YASA EEG-only REM F1 0.55 on 50 MESA test subjects), while forehead-trained models reach REM accuracy ≈0.89–0.91. [SS KQ2] ezscore-f's real-time model: κ 0.71–0.73 on ZMax, single-epoch capable. [G2 B] κ 0.30 is a binary gate-vs-GSSC κ on one in-sample night and bounds nothing about PSG agreement; GSSC was trained "mostly on C3, C4, F3, F4". [G2 A4, RI Q10] #167 hop proposal and the ≥60 s structural latency. [WR KQ2] frontal headbands over-call REM (Muse-S +6.4 min, Dreem +7.9/+25 min, ZMax 832 vs 467 events), so sustained evidence matters. [WR KQ7 inference] "a credible REMind validation plan can be fully executed on open data".

**Why no open project has it:** ezscore-f is the nearest: forehead-trained, real-time capable, MIT, but ZMax-trained, offline, with ZMax/DCM/CGX loaders only, no Muse loader, no gate/scheduler, and an independent group could not install it [VSS row 8, WR KQ8]. Dreamento's real-time TinySleepNet was trained on one person's nights with no published agreement and the repo has been unpushed since 2024-03 [VSS F]. NeuroTrainer is Sleep-EDF-trained with Muse integration "still in development" [VME row 10]. southsko/muse-sleep-dashboard is offline YASA [VSS row 15]. InteraXon's REM κ 0.85 is closed and measured on pre-Athena Muse-S [VWR row 1]. No open real-time REM detector is validated on any Muse [ME Q2, VME].

**Effort:** large — dataset ingestion (≈36 GB), a new source/loader, training code, harness v2, hop wiring with gate semantics, and CI-safe tests on a small synthetic BIDS fixture; months of part-time work; no new hardware.

**Risk / caveat:** BOAS is a Bitbrain Ikon headband, not a Muse — different electrode material, impedance, gain and reference — so BOAS results are transfer evidence (ezscore-f's own cross-device test was two nights of one participant [VSS C]); TP9/TP10 have no BOAS analogue; any Muse-specific claim needs Muse nights with expert or PSG labels, which do not exist publicly [VWR row 18] and are the owner's stated blocker (#116); a shorter hop increases false-positive exposure unless wall-time stability is preserved; detection accuracy is not cue efficacy.

### Initiative 3 — Cue-locked arousal scoring and adaptive volume titration on top of the epoch-level guard

**Extends:** `src/muse_tmr/protocol/arousal_guard.py` (epoch rows; `lower_volume_multiplier 0.50`, `pause_seconds 120`), `src/muse_tmr/audio/volume_calibration.py` (detectable/identifiable/comfortable, hard cap 0.20), `src/muse_tmr/validation/pilot4.py` (awakening log via `log-pilot4-awakening`, emergency stop), `docs/validation.md`.

**Build (issue-ready):**
1. `protocol/cue_arousal.py`: for every scheduler `play`, score a post-cue window (default 10 s) against a pre-cue baseline (≈20 s): frontal alpha 8–12 Hz and beta 15–30 Hz relative-power rise, EMG-band (e.g. 55–95 Hz, the band the meditation EMG check already uses) power rise on any channel, IMU motion burst, HR jump when PPG is present; write `cue_arousal_events.jsonl` with `arousal_flag`, reason codes and window values. Requires a sample-aligned buffer around the cue timestamp in the Pilot 4 loop, not 30 s rows.
2. Volume controller: per-night set-point starting at the calibrated `detectable` level; +1 step after N consecutive arousal-free cues up to `comfortable` (never above the hard cap); −1 step after any flagged arousal; a 45-min cue pause after an awakening the user attributes to a cue (existing awakening log or an app button); stricter REM settings than the NREM literature values; persist the closing set-point as the next night's start.
3. Metrics and gates: `arousal_per_cue`, `movement_events_per_cue` vs matched silent windows, `awakenings_attributed_to_cue`, `volume_steps_down` in `pilot4_summary.json` and `docs/validation.md`; Pilot 4/5 validators fail above a configured `arousal_per_cue` ceiling.
4. Tests: synthetic alpha/EMG bursts injected 2–8 s after a mock `play`; Pilot 3 replay regression.

**Evidence:** [TS KQ4, VTS row 9] Whitmore & Paller 2023: an arousal within 10 s of a cue turned the benefit into forgetting; soft cues at ≈28 dBA (31.7 % of the arousal threshold) still produced arousals after 43.0 % of cues; "the degree of arousal is more important than the objective intensity of the cue". [VTS row 10] SleepStim (Whitmore et al. 2022): the intensity set-point was lowered automatically when p(N3) fell during sounds, and capping intensity turned a null N = 61 result into a significant N = 24 one. [TS KQ4] Konkoly et al. 2024: 0.19 vs 0.10 movement events per cue, cues often woke users; Picard-Deland/Esfahani 2024 preprint: pause on EMG/alpha rise, resume one step lower, sleep disrupted in 23.7 % of cued REM periods; Lustenberger 2022: ±1.5 dB rules; Ngo & Staresina 2022: +6 dB titration until an EEG response without arousal. [VTS spot check] Coon et al. 2026: start at perceptual threshold + 10–20 dB then titrate, stricter settings in REM, log stimuli and arousals, user pause/stop. [WR KQ6, VWR S10] Philips SmartSleep: 15–30 Hz power detects micro-arousals, delaying or stopping stimulation. [TS KQ9] home arousals are the main risk named by Carbone & Diekelmann 2024.

**Why no open project has it:** home-tmr pauses and lowers the maximum by `ADAPTATION_STEP` after an arousal, but from Fitbit motion/HR, for N3, stale since 2022 [VCT row 5, ME Q3]. COsleep disengages on arousal and detects the hearing threshold in dB, but is OpenBCI/Linux lab software stale since 2023 [VCT row 2]. EazzZyLearn_pc plays the `.wav` at file amplitude with no volume scaling [G1 §3–4]. Dreamento and Taran-Douley have no guard. InteraXon's Auto-Snooze lowers an alarm, not a cue [G3 KQ4]. No consumer-EEG cueing tool scores arousal per cue from EEG + EMG-band + IMU + HR and titrates the volume both ways.

**Effort:** medium — the logic is pure, replay-testable Python like the existing guard, but it needs sample-aligned post-cue buffering in the night loop plus summary/validator changes; no hardware.

**Risk / caveat:** forehead-only EEG lacks occipital alpha and chin EMG, so arousal sensitivity is lower and the EMG-band proxy is unvalidated in humans [WR KQ3 gap]; the 64 Hz optics line and the ≈257.2 Hz true sample rate can masquerade as high-frequency power; software gain is not dB SPL [RI Q4 gap], so set-points are device-relative; no dose–response of REM awakening vs dB exists [WR KQ6 gap]; whether titration changes any outcome is untested and must be reported as a safety metric, not a benefit.

### Initiative 4 — EDF+/BIDS export and hypnogram import, with reproducible packaging

**Extends:** `src/muse_tmr/data/recorder.py` (`raw_amused.bin` + JSON/JSONL), the continuous-EEG reconstruction currently inside `scripts/validate_rem_detection.py` (zero-fill of >0.5 s gaps, resampling), `src/muse_tmr/annotations/rem_annotations.py`, `scripts/check_forbidden_files.py` (`*.edf`/`*.bdf` forbidden), `pyproject.toml` and `.github/workflows/guardrails.yml`.

**Build (issue-ready):**
1. Move raw → continuous reconstruction into `data/continuous.py` (sequence dedup from PR #182; gap policy either EDF+D discontinuous records or zero-fill with annotations, both documented in metadata).
2. `muse-tmr export-edf <recording_dir>`: EDF+ with TP9/AF7/AF8/TP10 in µV at 256 Hz (physical range set to the 1450 µV span so 14-bit data stays lossless in 16-bit), IMU and optics as separate signals or a sidecar; EDF+ annotations for recorder events, gate transitions, guard actions and scheduler `play/skip/pause/stop` with reason codes; hypnogram from the heuristic/personal model using standard texts ("Sleep stage R" etc.). Optional dependency group `[edf]` (edfio or pyedflib).
3. `muse-tmr export-bids`: `sub-<id>/ses-<date>/eeg/` with `_eeg.edf`, `channels.tsv` (EEG/MISC), `_eeg.json` (EEGReference near Fpz, PowerLineFrequency, SoftwareFilters, Manufacturer), `_events.tsv` for cues with HED tags, stages in a second `acq-scoring` events file (the community pattern that passes the validator); run `bids-validator` in CI on a synthetic export.
4. Import: `annotate-template --from-hypnogram <edf+ | events.tsv>` so an expert's scoring of the exported EDF, or a co-recorded device's hypnogram, becomes training/validation labels (feeds Initiative 2 step 5 and the Muse anchor night).
5. Packaging: PyPI release, pinned lower bounds, CI matrix Python 3.9–3.12 (3.8 is claimed, untested), Zenodo DOI per tag, `CITATION.cff`; whitelist one tiny synthetic `.edf` fixture in the forbidden-files check.

**Evidence:** [RI Q2/Q10, VRI A13] no EDF/BDF/BIDS/MNE export, `.edf` forbidden, MNE only in stager scripts. [SS KQ6] YASA, U-Sleep (web), Luna and ezscore-f all accept EDF or MNE `Raw`; EDF+ TALs carry standard hypnogram texts; BIDS-EEG has no sleep-stage vocabulary. [WR KQ7, VWR row 15] no sleep BEP exists (closest BEP044/045); community practice is stages in an `acq-scoring` events.tsv plus HED-SCORE tags. [WR KQ8] installability is judged (ezscore-f could not be installed by Parry & Briganti); Zenodo DOIs, pip and disclosed algorithm versions are what gave Portiloop, Dreamento, YASA and the Dreem datasets traction. [G2 A7] no PyPI package under any name. [VRI B2] Python 3.8 untested, `docs` extra builds nothing. [ME Q2] a Mind Monitor forum user asking how to get Muse CSV into EDF for YASA, unanswered. [G3 KQ5] InteraXon offers EDF/CSV export only to paying research partners.

**Why no open project has it:** no open Muse overnight recorder writes EDF+/BIDS with cue annotations: muse-sleep-dashboard reads CSV [VSS row 15]; EazzZyLearn_pc writes comma-separated `.txt` [G1 §6]; eeg-neurolyze has EEG-BIDS export but "has not yet been tested with an actual Muse S Athena" and does no sleep [ME Q1]; neurofeed exports EDF/CSV but has no Athena optics and no sleep logic [ME Q1]; Dreamento relies on Hypnodyne's recorder [CT]; ZMax EDF is vendor software. An Athena night that opens in YASA/Luna/MNE with the cue log as annotations would be unique in the Muse ecosystem.

**Effort:** medium — the reconstruction exists and only moves; EDF writing is a dependency; BIDS is layout plus a validator in CI; packaging is small; roughly two to three weeks part-time.

**Risk / caveat:** without a sleep BEP the layout may need revision; gap handling (EDF+D vs zero-fill) changes stager behaviour and must be declared; exports contain personal sleep EEG and stay gitignored under the repository's data rules; optics channels have no standard BIDS type; AGPL (GSSC) and CC BY-NC (SleepFM) licences of reference tools must not be mixed into the MIT package.

### Initiative 5 — Protocol-fidelity instrumentation for a sham-controlled N-of-1 design

**Extends:** `src/muse_tmr/protocol/randomization.py` (item-level seeded cued/uncued), `src/muse_tmr/reports/morning_retest.py` (blind, next morning), `src/muse_tmr/reports/dream_report.py` (self-report), `src/muse_tmr/reports/analysis.py` (descriptive with `limitations`), `src/muse_tmr/app/morning.py` (never reveals `cue_condition`), `docs/validation.md`.

**Build (issue-ready):**
1. Night-level arms: seeded sequence of {trained-cue, untrained-sound sham, no-cue} nights in blocks with washout nights; the scheduler plays the sham sound under identical gate/timing/volume rules; the arm is hidden from every morning page (the rule the Morning tab already enforces for `cue_condition`); analysis compares arms on `lucid`, `cues_heard`, incorporation, `arousal_per_cue` and awakenings.
2. Delayed retest: `record-puzzle-retest --kind delayed --days 7` (and the app equivalent); analysis of next-morning vs one-week outcomes per condition.
3. Blind-coding schema: a rater form separate from the dreamer's self-report (cue incorporation direct/indirect, conceptual incorporation, lucidity items in the LuCiD insight style), stored before unblinding; analysis uses rater codes, self-report stays secondary.
4. LRLR-ready marking: a morning field "attempted eye signal at ≈HH:MM"; an offline command that plots the low-passed AF7−AF8 trace (Initiative 1) ±60 s around that time for manual marking (Dreamento-style event code), exported into the EDF+ annotations (Initiative 4). Explicitly no automatic LRLR detection.
5. N-of-1 export: per-night table (arm, cue counts, safety metrics, outcomes), a SCRIBE 2016 / CENT 2015 checklist stub and an OSF preregistration template for a Pilot 5 series in `docs/`; descriptive statistics only, `limitations` extended with `single_subject`, `sham_detectable`, `carry_over_possible`.

**Evidence:** [TS KQ6/KQ7/KQ9, VTS] Konkoly et al. 2024 Exp 2 used untrained-sound and no-cue nights with participants blind to the control nights; Konkoly et al. 2026 used two blind raters and found incorporation, not cueing, predicted solving; the Picard-Deland/Dresler 2024 preprint is sham-controlled and preregistered; Pereira 2023 and Rakowska 2021 saw effects only at one week / ten days; SCRIBE/CENT and Konigorski 2026 give single-participant reporting and analysis frameworks; Göldi & Rasch 2019 saw benefit only on night 3 (habituation). [G4 B] no automatic LRLR detector with sensitivity/false-positive rate exists in 2021–2026 literature; all verification is human-rated with 2-of-3 or 3-of-4 majority; the note recommends "LRLR-ready logging, not LRLR detection". [CT KQ4, VCT item 3] none of the inspected open projects implements seeded randomization + blind retest + analysis in software; COsleep has sham/stim blinding only; Taran-Douley lists sham nights as unimplemented. [G1 §9] brainwave_opensync offers seeded blinded n-of-1 blocks but measures no physiology.

**Why no open project has it:** COsleep's blinding is NREM, OpenBCI, stale [VCT row 2]; SMACC records dream reports and surveys but is an experimenter console with no sensing [VCT row 8]; home-tmr includes a task but no randomization code [VCT row 5]; brainwave_opensync randomizes arms without physiology [G1 §9]. None couples physiology-gated cueing with night-level sham, item-level randomization, delayed retest, blind coding and N-of-1 export.

**Effort:** medium — protocol/report code following the existing dataclass + versioned-JSON pattern, synthetic tests, a small viewer reusing `report_style`; a few weeks.

**Risk / caveat:** at n = 1 the experimenter cannot be blinded, the "untrained" sham may be recognised, carry-over and habituation across nights are real, and power for any behavioural contrast is low, so outputs stay descriptive; preregistration buys credibility, not evidence; the repository's banned wording ("validated lucid dreaming", "proven") applies to every new report.

### Initiative 6 — Tonic/phasic REM sub-gate as a labelled research option

**Extends:** `src/muse_tmr/models/rem_gate.py` (`RemGateDecision` metadata, never `gate_open`), `src/muse_tmr/protocol/tmr_scheduler.py` (skip reason codes), Initiative 1's REM-event stream.

**Build (issue-ready):**
1. Microstate estimator: `phasic_window_active` = a REM-event burst (≥2 events within ≈3 s) within the last T seconds on the low-passed AF7−AF8 trace; exposed as gate metadata.
2. Scheduler policy `rem_microstate_policy ∈ {any (default), tonic_only, phasic_only}`; `skip` reason codes `phasic_window_active` / `tonic_required`; every `play` records the microstate label and the age of the last REM event.
3. Replay report of the cue budget per policy per night (how many cues each policy leaves), published before any outcome claim.
4. Analysis hook joining per-cue microstate labels with `arousal_per_cue` (Initiative 3) and incorporation codes (Initiative 5).

**Evidence:** [TS KQ5] Simor et al. 2020: tonic REM has lower awakening thresholds and stronger evoked responses; Koroma et al. 2020: informative speech is suppressed during rapid-eye-movement bursts; Borghese 2022 lists ignoring tonic/phasic as a limitation; no study has compared TMR/TLR outcomes between microstates. [WR KQ6 inference] a REM-burst detector on AF7/AF8 can serve as REM evidence and as a phasic-window indicator, unvalidated against EOG scoring. [G4 B(3)] the only 2021–2026 automated phasic/tonic tool (Nagy et al. 2026) is single-channel EOG and offline; no frontal-EEG-only variant exists.

**Why no open project has it:** SNOOZ and Nagy 2026 classify phasic/tonic from EOG offline [WR KQ6]; Dreamento has no microstate logic; no cueing engine exposes a microstate policy.

**Effort:** small once Initiative 1 exists (flag, reason codes, metadata, tests, one replay table); validation is large and may never be conclusive at n = 1.

**Risk / caveat:** the direction of any benefit is unknown and may differ between lucidity cues (tonic = more responsive but more arousable) and memory cues; phasic windows are exactly when AF7/AF8 are most EOG-contaminated, so the REM-event detector and the microstate label are not independent; there is no EOG ground truth on Muse; this ships as a hypothesis-generating flag with default `any` and is never presented as an efficacy feature.

### Initiative 7 — Athena optics: ECG-referenced validation of forehead PPG, optics duty-cycling, raw-optics archive (not fNIRS REM detection)

4. Raw-optics archive plus exploratory relative ΔHbO/ΔHbR (modified Beer–Lambert with unknown DPF and geometry, reported as relative optical-density change) in a stage-resolved descriptive side report, decoupled from the detector and gate, labelled unvalidated.

**Evidence:** [ME Q1/Q5, VME rows 3–4/6] no library computes HbO/HbR: muse-lsl #237 ("we don't currently compute those … requires wavelength and source–detector metadata that we don't currently have"), OpenMuse #23 ("somewhat unclear & unvalidated", firmware changed optics), BrainFlow exposes optical rows only, muse-monitor's ΔHbO is "exploratory" with "unverified wavelength mapping"; the note concludes whoever publishes a validated extraction "would become the reference implementation". **Why no open project has it:** muse-monitor computes HR/HRV and exploratory ΔHbO from Athena optics but validates nothing and does no sleep [ME Q1]; OpenMuse lists "validate the best PPG signal extraction method" as open roadmap [VME row 4]; BrainFlow deliberately does not convert optics to PPG [VME row 6]; InteraXon's SpO₂/fNIRS pipelines are closed and for research partners [VME row 13]. No open project pairs Athena optics with chest ECG overnight; REMind already records both.

**Effort:** medium — steps 1–2 are analysis on data the repo already captures (a few weeks); step 3 is BLE/recorder work with reconnect risk (the owner's own macOS reconnect fix in BrainFlow #837 shows how fragile this layer is [VME item 10]); step 4 is small and of low scientific value.

**Risk / caveat:** optics cost ≈4.3 h of battery and add a 64 Hz line to the EEG, so all-night PPG trades against EEG quality and night completeness; forehead PPG has motion artifacts; PPG is not expected to fix REM false positives (fusion evidence); without published wavelengths and geometry, fNIRS outputs are relative and cannot be reported as HbO/HbR; none of this bears on lucidity or memory outcomes.

## 3. What the repository should not try to compete on

Raw BLE/LSL streaming and visualisation are solved by larger projects (muse-lsl ≈781 stars with Athena since June 2026; BrainFlow ≈1.8k stars, seven CI badges, Athena since 5.22.0 in May 2026; OpenMuse; muse-rs): keep the `openmuse_lsl_source`/`brainflow_source` adapters, push Athena fixes upstream as with BrainFlow #837, and change the forked amused-py layer only for protocol fixes [ME Q5, VME]. General-purpose PSG staging (YASA, U-Sleep, GSSC, SleepFM, trained on thousands to tens of thousands of nights) should be used as references, not rebuilt; REMind's detector is a frontal, causal, REM-focused component. NREM slow-oscillation phase-locked CLAS is where EazzZyLearn, Taran-Douley, COsleep, Portiloop and every commercial headband (Dreem/Beacon, FRENZ, Elemind, SleepLoop, Philips) already compete and needs the ≈100–150 ms latency a 30 s-epoch BLE pipeline is not built for; REM is where the open field is empty [CT, G1, VTS spot check]. Automatic eye-signal (LRLR) detection and two-way dream communication should not be a product claim: no algorithm with a reported sensitivity or false-positive rate exists in the 2021–2026 literature and every verification was human-rated under PSG [G4 B]; ship LRLR-ready marking (Initiative 5) instead. fNIRS-based REM or arousal detection has no supporting study, Athena's optical geometry is unpublished and the signal is slow and low-SNR [WR KQ5]; limit optics to ECG-referenced PPG and an exploratory archive (Initiative 7). Do not try to out-detect the vendor: InteraXon's closed model reached REM κ 0.85 on Muse-S in a lab study and already ships REM-timed waking and research TMR for partners [VWR row 1, G3]; REMind's defensible claim is open code, non-waking REM-gated cueing, protocol controls and auditable logs, not detection superiority. Do not claim lucid-dreaming, memory or clinical efficacy: the best-controlled recent studies found induction not different from sham (Picard-Deland 2024 preprint) and REM puzzle cueing with no overall effect (Konkoly 2026) [TS KQ2–KQ3]; report fidelity and safety metrics with limitations, as `docs/validation.md` already requires. Consumer UX, app-store distribution, cloud sync and telemetry are outside the n = 1 research scope and forbidden by the repository's own rules.
