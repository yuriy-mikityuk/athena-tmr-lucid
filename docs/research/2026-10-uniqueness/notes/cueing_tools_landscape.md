# Sleep-time cueing tools landscape: TMR / TLR / lucid-dream induction / closed-loop sleep stimulation (status as of 2026-10-21)

Scope note: this file covers *other* projects only; remind-eeg itself is covered by other researchers. "Stale" below means no code pushed since 2023 (GitHub `pushed_at`), as the assignment requested. Star counts and push dates were read on 2026-10-21 from the GitHub search API via the GitHub MCP tool unless another source is cited; treat them as approximate (±). The web-search budget ran out near the end, so a few items (Sleep as Android docs, Elemind/FRENZ/Somnee primary papers, Bitbrain) are left as explicit gaps rather than guessed.

## Key Question 1: Open-source TMR / sleep-cueing software and devices (labs, toolboxes, ZMax tools, CLAS code, Portiloop, Dormio, Lucid Scribe, legacy devices)

### Takeaway
There is a thin but real open-source layer: two research-grade closed-loop toolboxes (COsleep for OpenBCI Cyton, Portiloop as an open-hardware spindle detector), one dream-engineering toolbox for the ZMax headband (Dreamento), one lab home-TMR stack for phone+Fitbit (home-tmr/SleepStim), one hypnagogia device (Dormio/openSleep), and a long-running hobbyist/indie ecosystem (Lucid Scribe plugins, INSPEC camera). None of them is a maintained, consumer-EEG-headband, REM-gated cueing engine with a built-in experimental protocol; most are either stale (last push 2019–2023), NREM/slow-oscillation oriented, or do not detect REM in real time at all.

#### Lab-released TMR code (Paller, Rasch, Schreiner, Lewis/Cardiff, Cairney/York)
- The only lab-released *home cueing stack* found is Northwestern Cognitive Neuroscience Lab's `home-tmr` ("code for the Cognitive Neuroscience Lab home TMR project"; MIT; Android app + Fitbit watch apps; config parameters ONSET_TIME, OFFSET_TIME, ISI, VOLUME_INC, CUE_NOISE_MAX, MAX_STIM, ADAPTATION_STEP, E_STOP, BACKOFF_TIME; logs MediaLog with played files, timestamps and volumes and fitbitdata.txt with raw sensor data and p(S3); README warns the default telemetry server "is not secured or HIPPAA compliant") — [GitHub](https://github.com/nathanww/home-tmr). #### Hypnodyne ZMax and its open ecosystem
- ZMax official page: EEG F7-Fpz and F8-Fpz with Ag/AgCl hydrogel patch; also HR, SpO2, forehead temperature, nasal airflow (with sensor), snoring sound, head position/movement, ambient light, room temperature/humidity; detected features include "REMs" and "slow eye movements"; the device exposes a TCP/IP data socket usable from MATLAB, Python, C++, C#, Java, PHP with ~3.5 ms proprietary-radio latency; JavaScript scripting "can detect REM and play sounds"; the site describes closed-loop auditory stimulation (CLAS) and "delta-wave potentiation"; raw EDF is stored locally with no cloud/subscription; autoscoring is a paid proprietary service cited at ~89% agreement with human consensus; dedicated lucid-dreaming and TMR/CLAS pages exist; pricing is not public — [Hypnodyne ZMax page](https://hypnodynecorp.com/zmax.php).
- Mota-Rolim et al. 2019 classify ZMax as "not open-source, though it can be scripted and interfaced with other languages", on sale since 2018, the most expensive and most technically documented of ten lucid-dream devices — [Frontiers / PMC6517539](https://pmc.ncbi.nlm.nih.gov/articles/PMC6517539).
- Dreamento (Donders: Jafarzadeh Esfahani, Daraie, Weber, Dresler) is the open Python layer on top of ZMax: real-time recording via HDServer/HDRecorder, spectrogram, autoscoring, visual/auditory/tactile stimulation, text-to-speech, annotations; offline: EEG eye-movement detection in REM, SO/spindle detection, consensus scoring — [GitHub](https://github.com/dreamento/dreamento), [arXiv](https://arxiv.org/abs/2207.03977v2).
- A 2025 University of Amsterdam preprint (Jongejan, van der Heijden, Talamini) ran modeling-based closed-loop acoustic SO stimulation on a "self-applicable EEG headband with forehead electrodes" validated against PSG; the method (M-CLNS) is patented by Talamini and no code link is given — [bioRxiv 2025.03.09.642252](https://www.biorxiv.org/content/10.1101/2025.03.09.642252v1); a secondary review identifies the headband as ZMax with 26 participants and manual staging — [The Moonlight review](https://themoonlight.io/review/biorxiv/deepening-sleep-using-an-eeg-wearable-featuring-modeling-based-closed-loop-neurostimulation).

#### Dreem research tools
- Dreem stopped direct-to-consumer sales in March 2021; Beacon Biosignals acquired Dreem's R&D arm in July 2023; the Dreem 3S got FDA 510(k) clearance and was rebranded Waveband for clinical research — [Sleep Review](https://sleepreviewmag.com/sleep-diagnostics/connected-care/remote-monitoring/beacon-biosignals-bolsters-sleep-medicine-research-acquisition-dreem/), [MedTech Dive](https://www.medtechdive.com/news/beacon-biosignals-fda-clearance-sleep-tracking-headband/693901/).
- Dreem's own CLAS validation (Rythm authors): N3 detection sensitivity 0.70 / specificity 0.90, SO ascending-phase accuracy 45±52°, +39.5% delta power, n=20 double-blind crossover plus 90 home users; code availability not stated — [bioRxiv 181529](https://www.biorxiv.org/content/10.1101/181529v1). A registered trial uses the Dreem 2 with 100-ms pink-noise pulses on the SO ascending phase in N3 and a no-sound sham arm — [ClinicalTrials.gov NCT05024578](https://clinicaltrials.gov/study/NCT05024578).

#### SleepLoop (ETH Zurich / UZH / Ulm)
- SleepBand: up to 8 EEG/biopotential channels, 24-bit ADC, ARM Cortex-M4, ~24 h battery, Bluetooth/Wi-Fi, microSD; autonomous algorithms time tones to slow waves; home trial in older adults (Lustenberger et al. 2022) found robust slow-wave increases with large inter-individual variability; spin-off Tosoo AG; open-source status not stated — [Ulm project page](https://uni-ulm.de/en/in/bmt/forschung/projekte/sleeploop). Press: 16 participants aged 60–80, alternating two-week stimulation blocks over four weeks; Tosoo will sell only via prescription — [Neuroscience News](https://neurosciencenews.com/sleeploop-neurotech-sleep-20346/), [Futurity](https://www.futurity.org/sleeploop-deep-sleep-2723142/).

### Inferences
- The open-source field splits into (a) NREM/slow-oscillation CLAS tooling for research EEG (COsleep, Portiloop, Dreem/SleepLoop validations) and (b) REM-oriented lucid-dream hobby tooling with little or no validation (Lucid Scribe plugins, INSPEC, OpenLD). The only open project that both targets REM and ships a staging model is rmallela26/TLR (Apple Watch, 5 commits).
- The best-documented open safety logic lives in COsleep (auto-disengage on arousal, hearing-threshold calibration, blinding) and home-tmr (E_STOP, backoff, adaptive volume ceiling), both now stale; nothing comparable was found for a consumer EEG headband.
- Hypnodyne's ZMax is the de-facto research platform for home REM cueing because of its TCP socket and JS "detect REM and play sounds" scripting, but the staging/REM algorithms are proprietary and paid; Dreamento is the open layer on top.

## Key Question 2: Targeted lucidity reactivation specifically — released code, stimuli, apps and GitHub repos

### Takeaway
TLR has exactly two open-source implementations found: Northwestern's Android "Dive" app (MIT App Inventor; code said to be on GitHub but the repository was not located; no REM detection, fixed 6-hour delay) and Mallela & Mallett's MIT-licensed iOS/watchOS app (Apple Watch staging; 7 stars, 5 commits). The lab-grade TLR studies (Carr et al. 2020/2023) released no code or stimuli that could be found; the cue itself (three rising pure tones 400/600/800 Hz, ~650 ms) is documented in papers and a trial protocol.

### Cited Findings
- Carr, Konkoly, Mallett, Edwards, Appel & Blagrove, "Combining presleep cognitive training and REM-sleep stimulation in a laboratory morning nap for lucid dream induction", Psychology of Consciousness (DOI 10.1037/cns0000227; records list 2020 and vol. 10(4) 2023): signal-verified lucid dreams in 50% of cued vs 17% of uncued participants; three successful participants had never had a lucid dream — [Swansea Cronfa](https://cronfa.swansea.ac.uk/Record/cronfa53997). No OSF/code/stimulus deposit was found in search.
- TLR cue specification used by the Paller group in a registered narcolepsy-nightmare protocol: three rising pure tones (400, 600, 800 Hz), ~650 ms, trained before sleep — [ClinicalTrials.gov NCT05709873 protocol PDF](https://cdn.clinicaltrials.gov/large-docs/73/NCT05709873/Prot_SAP_000.pdf).
- Konkoly, Whitmore, Mallett, Mazurek & Paller 2024 (Consciousness & Cognition 125:103759), at-home TLR app: built with MIT App Inventor for Android; "code on GitHub", latest version on Google Play; no REM detection or sleep monitoring; cueing began a fixed 6 h after training; Exp1 cues every 20–40 s, accelerometer paused cueing 5 min after movement (1 min in Exp2), 45-min pause if the user woke and chose to continue; cue was either three ascending beeps (400/600/800 Hz, ~650 ms) or a 1000-ms violin; intensity started at discrimination threshold and rose 0.16%/cue (0.08% in slow mode), capped once a cue was reported incorporated into a dream; Exp1 n=19 completers: lucid dreams 0.74→2.11/week (p=.007), 14 of 38 lucid dreams attributed to cues; Exp2: 416 used the app, 120 completed ≥1 night per condition, 50 completed all 7 nights; randomized to TLR-cue / untrained-cue / no-cue, controls received TLR on nights 1,3,5,7 and untrained/no cue on 2,4,6 and "did not know about the control nights"; TLR vs combined controls interaction p=.01, untrained-cue p=.03, no-cue p=.77; night-2 OR=3.61 (p=.006); cues increased movement-detected disruption (0.19 vs 0.10 per cue, p=.002); data available on request — [PMC11542932](https://pmc.ncbi.nlm.nih.gov/articles/PMC11542932), [Northwestern PDF](https://faculty.wcas.northwestern.edu/~paller/C&C24.pdf).
- The Google Play package for that app is `com.neurelectrics.dive`; Konkoly: "The app used in this research is under continual development"; the researchers "have begun working with InteraXon, the maker of the Muse-S headband" to add REM detection — [PsyPost](https://www.psypost.org/lucid-dreaming-app-triples-users-awareness-in-dreams-study-finds/). The Play Store URL for that package returned HTTP 404 when fetched on 2026-10-21 (own observation); Gigazine reported the app cannot be installed on Android 15 — [Gigazine](https://wbgsv0b.gigazine.net/gsc_news/en/20241118-lucid-dream).
- MIT Media Lab "Dive" project (with Northwestern CNL): "adapts a technique previously used to induce lucid dreams in a sleep lab by presenting sounds during REM sleep"; the team is testing whether smartwatch data or phone motion sensors on the bed can detect REM — [MIT Media Lab](https://www-prod.media.mit.edu/projects/dive-1/overview/). A Fitbit gallery app "Dream" by Nathan Whitmore supports the Northwestern lucid-dreaming study and points to the same Android companion package; it describes timed cue sounds, questionnaires and a <30-min nightly training, with "sleep disruption" as the main risk — [Fitbit Gallery](https://gallery.fitbit.com/details/80917cd9-4e00-4842-b59f-41aa23209254).
- Mallela & Mallett 2024, "Targeted lucidity reactivation implemented in an open-source watchOS app", IJoDR 17(2):143–147, DOI 10.11588/ijodr.2024.2.100797: iOS/watchOS app performing pre-sleep training, real-time sleep staging from Apple Watch measures, and REM cueing — [IJoDR](https://journals.ub.uni-heidelberg.de/index.php/IJoDR/article/view/100797). Repo: MIT license, Swift, classifier in `server/` (processing.py, model.py) hosted on Google Kubernetes Engine, 5 commits, 7 stars, created 2024-03-05, last push 2024-10-29; no validation data, no App Store/TestFlight distribution — [GitHub rmallela26/TLR](https://github.com/rmallela26/TLR).
- Mallett's other TLR/TMR study code: remrama/bct-tlr ("Inducing lucid dreams with a breathing task", 2022), remrama/relax-tmr ("Cueing a guided relaxation tape during SWS", 2023); Wolk et al. 2024 IJoDR "Lucid dreams from reactivating mindfulness during REM sleep" — [GitHub user remrama](https://github.com/remrama), [Paller lab publications](https://sites.northwestern.edu/pallerlab/publications/).
- Paller-lab TLR line 2024–2026 (no code links on the lab page): Mundt et al. 2025 J Sleep Res pilot of CBT + TLR for narcolepsy nightmares; Morris et al. 2025 Neuroscience of Consciousness (lucid dreaming of a VR experience); Morris et al. 2026 Brain Sciences 16(3):315 (lucid dream induction via compassion practice); Konkoly et al. 2025 Neuropsychologia (sounds in REM reactivate waking experiences) — [Paller lab publications](https://sites.northwestern.edu/pallerlab/publications/).
- Lucid Scribe's mobile app markets "targeted lucidity reactivation (TLR)" alongside TDI, MILD, FILD and SSILD; the lucidcode GitHub org publishes the INSPEC firmware and sensor plugins but not the core app — [lucidcode.com](https://lucidcode.com/), [GitHub lucidcode](https://github.com/lucidcode/Halovision-INSPEC).
- Mallett co-authored the DREAM database (Nature Communications 2025): 20 datasets, 505 participants, 2,643 awakenings with dream reports — an open dataset, not a cueing tool — [UFRN record](https://repositorio.ufrn.br/items/5e0d538d-6818-4089-b30a-cb0dcb2343e9/full).

### Inferences
- The Konkoly 2024 Exp2 design (randomized groups, interleaved control nights unknown to participants) is the only published *blinded, randomized* home TLR protocol, but the blinding and scheduling live in the study procedure, not in a reusable open engine; the app itself is timer-based with movement pauses.
- Northwestern's stated move toward Muse S for REM detection means the leading TLR lab is heading toward exactly the headband+REM-gate configuration, but no public code for it was found as of October 2026.

### Gaps
- The GitHub repository for the Konkoly/Dive Android app was not located (search budget exhausted before a targeted repo search); the paper only says "code on GitHub".
- Carr et al. 2020/2023 stimuli/scripts: no OSF or repo found.
- Whether the Dive app is still downloadable is unclear (404 at fetch; Android 15 incompatibility reported).

## Key Question 3: Commercial / closed devices doing sleep-stage-gated stimulation (for contrast)

### Takeaway
Commercial closed-loop sleep devices are almost all NREM/sleep-onset oriented (Elemind, FRENZ, Somnee, SleepLoop/Tosoo, Dreem→Beacon Waveband) with proprietary algorithms and company-reported validation; the only REM/lucid-dream commercial players are Hypnodyne ZMax (research, scriptable, closed algorithms), Prophetic (ultrasound, now "Dual"/"Phase", shipping 2026–2027, no neural sensor on the cheaper unit) and watch apps like Lucidly (claimed >80% REM accuracy, unverified).

### Cited Findings
- **Elemind**: EEG headband feeding "Elemind's proprietary algorithms" that generate audio via a bone-conduction driver; audio tapers out once sleep is detected; a small study in sleep-onset insomnia cut time-to-sleep by 10–15 min; commercial launch 2024 — [MIT News](https://news.mit.edu/2024/startup-elemind-helps-people-fall-asleep-0925). Review lists $349 and ~8 h battery — [GearJunkie](https://gearjunkie.com/technology/elemind-sleep-headband-review). Elemind's /science page returned 404 at fetch time; no peer-reviewed Elemind trial was located.
- **FRENZ Brainband (Earable Neuroscience)**: bone-conduction audio; "plays pink noise at precise moments of the brain's slow-wave oscillation phase"; a Scientific Reports study with Oxford and Colorado is reported as 24.1-min sleep-onset reduction in 377 individuals and 88% (elsewhere 89%) staging precision vs PSG; price ~USD 490 (Apr 2024); figures vary across trade-press sources — [Sleep Review](https://sleepreviewmag.com/sleep-diagnostics/consumer-sleep-tracking/wearable-sleep-trackers/wearable-brainband-uses-ai-audio-improve-sleep/), [Sleep Review (availability)](https://sleepreviewmag.com/sleep-treatments/therapy-devices/sound-acoustic-therapies/frenz-brainband-audio-therapy-better-sleep-available/), [Wearable Technologies](https://wearable-technologies.com/news/frenz-brainband-revolutionizing-sleep-and-focus-enhancement).
- **Somnee (StimScience)**: EEG sensor plus transcranial electrical stimulation; typical use is a 15-min pre-bed session, overnight wear optional; 2025 "next-gen" relaunch with "proprietary AI"; an API for select researchers/partners/clinicians planned for 2026; company claims it "cuts the time to fall asleep in half", "22 clinical studies", "24 patents" (unverified here; the BusinessWire release returned 403 at fetch) — [Efferent Substack](https://efferent.substack.com/p/company-spotlight-somnee), [Fitt Insider press release](https://insider.fitt.co/press-release/somnee-launches-next-gen-ai-powered-smart-sleep-headband-for-faster-sleep-deeper-recovery-and-optimized-sleep-performance/).
- **Dreem / Beacon Biosignals**: consumer sales ended March 2021; R&D acquired by Beacon July 2023; Dreem 3S FDA-cleared and rebranded Waveband for clinical trials — [Sleep Review](https://sleepreviewmag.com/sleep-diagnostics/connected-care/remote-monitoring/beacon-biosignals-bolsters-sleep-medicine-research-acquisition-dreem/), [MedTech Dive](https://www.medtechdive.com/news/beacon-biosignals-fda-clearance-sleep-tracking-headband/693901/). CLAS validation: N3 sensitivity 0.70/specificity 0.90, 45±52° phase accuracy, +39.5% delta power — [bioRxiv 181529](https://www.biorxiv.org/content/10.1101/181529v1).
- **SleepLoop / Tosoo AG**: prescription-only clinical route; see Q1 — [Futurity](https://www.futurity.org/sleeploop-deep-sleep-2723142/), [Ulm](https://uni-ulm.de/en/in/bmt/forschung/projekte/sleeploop).
- **Hypnodyne ZMax**: closed algorithms, paid autoscoring (~89% vs consensus), but TCP socket + JavaScript scripting that "can detect REM and play sounds", CLAS and TMR pages — [Hypnodyne](https://hypnodynecorp.com/zmax.php).
- **Prophetic**: 2023–2024 coverage described the "Halo" ultrasound headband run on the Morpheus-1 model at an estimated $2,000 with $100 deposits (2,926 registrations), testing with the Donders Institute and TTP, and a late-2025 ship target; scientists were skeptical and no efficacy proof was offered — [Decrypt](https://decrypt.co/200538/halo-prophetic-ai-device-lucid-dreams), [Live Science](https://livescience.com/technology/virtual-reality/ultrasonic-headband-induces-lucid-dreams-using-ai-its-creators-claim-but-an-expert-remains-skeptical), [Yahoo/Business Insider](https://ca.news.yahoo.com/now-sign-try-2-000-174844056.html). As of 2026-10-21 the company site (propheticai.co → prophetic.com) no longer lists "Halo": it sells "Dual" ($449; no neural sensors; fixed-focus ultrasound lens; batch 1 sold out, shipping end of 2026; batch 2 early 2027) and "Phase" ($1,299; prefrontal fNIRS sensing; "closed-loop" AI-adjusted targeting; shipping mid-2027); it cites a "2026 Q1 beta" with sham-vs-stimulation survey charts (recall, vividness, continuity, clarity, agency; no N or statistics) and an EEG ERSP showing beta/gamma increase; FAQ says products are not medical devices — [prophetic.com](https://www.prophetic.com/).
- **Lucidly (5Path LLC, iOS/watchOS)**: Apple Watch health data → neural-network REM estimate → haptic/audible alerts; claims "overall model accuracy > 80%" while stating "REM inference is an approximation"; $5.99/mo or $39.99/yr; v1.15.1 (March 2025); 3.2/5 from 19 ratings — [App Store](https://apps.apple.com/app/id1566419183).
- **Lucid Scribe + INSPEC**: INSPEC is a camera that "detects REM sleep through eye-area video analysis without electrodes" and works with the Lucid Scribe app for light/sound/vibration cues; the developer claims the desktop tool is cited in 20+ publications (self-reported) — [Product Hunt](https://www.producthunt.com/p/inspec-lucid-dreaming-device/inspec-lucid-dreaming-device), [lucidcode.com](https://lucidcode.com/).
- **Sleep as Android**: documented as accelerometer/sonar sleep tracking with smart wake-up; no source confirming a REM-detected lucid-cue feature was found (its docs site redirected and the search budget was exhausted before confirming) — [LinuxInsider](https://www.linuxinsider.com/?p=87429), [awesome-lucid-dreams](https://github.com/IAmCoder/awesome-lucid-dreams).
- **Legacy consumer devices** (NovaDreamer discontinued 2004; Remee timer-only; REM-Dreamer infrared; Aurora/Neuroon defunct or untested; LucidCatcher/Aladdin tACS delayed) — [PMC6517539](https://pmc.ncbi.nlm.nih.gov/articles/PMC6517539).
- **Philips SmartSleep**: a commercial CLAS headband trial protocol exists (NCT03911154) — [ClinicalTrials.gov PDF](https://cdn.clinicaltrials.gov/large-docs/54/NCT03911154/Prot_SAP_ICF_001.pdf); current product status not researched.

### Inferences
- Across commercial devices, "closed-loop" means proprietary on-device staging with no auditable logs for the user; validation is company-sponsored (Dreem/Rythm authors, FRENZ press figures, Elemind small study) and sleep-onset/SWS oriented.
- Prophetic's pivot from a $2,000 "Halo" to a $449 sensor-less "Dual" indicates that REM-gated closed-loop lucidity hardware did not ship by the promised late-2025 date; the only sensing unit (Phase) is fNIRS, not EEG, and ships mid-2027 at the earliest.

### Gaps
- Bitbrain: no sleep closed-loop product or research was found; the query returned only unrelated CLAS trials.
- Muse app's own sleep features were deliberately not researched (covered by another researcher).
- Primary papers for Elemind and FRENZ, and Somnee's clinical-study list, were not retrieved (404/403 and search budget).
- Status of iBand+, Aurora and Neuroon after 2019 unconfirmed.

## Key Question 4: Which projects implement an actual experimental protocol in software (randomization, blinding, retests, analysis) and which log structured events

### Takeaway
Only three open tools carry any experimental-protocol logic: COsleep (sham/stimulation blinding, full marker/stimulation logging), SMACC (experimenter console with biocalibration, dream reports, surveys and a detailed per-run event log) and home-tmr (stimulation caps, arousal backoff, cue/volume logs plus a spatial task). No open project found implements seeded cued-vs-uncued item randomization plus blind morning retest plus analysis inside the software; those steps were done in study procedure (Konkoly 2024 Exp2, SleepStim) rather than code.

### Cited Findings
- COsleep README lists "sham/stimulation blinding for experiments", "logging of all markers and stimulation actions", "imputation and logging of lost samples", "online volume adjustment and hearing-threshold detection", "automatic disengagement of stimulation on arousal" — [GitHub](https://github.com/Frederik-D-Weber/cosleep).
- SMACC: audio cue designer, visual cues (BlinkStick/Hue), masking noise, "timed, marked biocalibration tasks", dream-report recording and surveys, two-way intercom, EEG port codes over LSL or TTL, EEG annotator, and "a detailed event log for every run"; used in the Paller and Carr labs; GPL-3.0; last push 2026-07-08 — [GitHub](https://github.com/remrama/smacc).
- home-tmr: MediaLog (played sound files, timestamps, volumes), fitbitdata.txt (raw sensor data and p(S3)), BedtimeTaskLog, live HTTP telemetry; MAX_STIM, E_STOP, BACKOFF_TIME, ADAPTATION_STEP; a "simple spatial memory task for Android" that integrates with the app; no randomization code described — [GitHub](https://github.com/nathanww/home-tmr). The SleepStim paper's design cued half of learned object locations (within-subject) over three nights — [bioRxiv](https://www.biorxiv.org/content/10.1101/2022.06.28.497977v1).
- Konkoly 2024 Exp2 randomization (TLR-cue / untrained-cue / no-cue groups) and participant-blind control nights are described as study design; the app logged movement-detected disruptions per cue (0.19 vs 0.10) — [PMC11542932](https://pmc.ncbi.nlm.nih.gov/articles/PMC11542932).
- Portiloop software logs recordings with lost-sample statistics and streams raw EEG via LSL/CSV; no protocol layer — [GitHub](https://github.com/Portiloop/portiloop-software).
- Dreamento manages "automatic and manual event annotations" and supports consensus scoring from up to three scorers offline; no randomization/retest — [GitHub](https://github.com/dreamento/dreamento).
- Taran-Douley/closed-loop-sleep lists "randomised sham nights" and a hard volume cap as unimplemented Phase 2 items — [GitHub](https://github.com/Taran-Douley/closed-loop-sleep).
- occult-kranti/brainwave_opensync advertises "blinded self-experiments" for binaural/lucid-dream cues (1 star, created 2026-09; not inspected further) — [GitHub search](https://github.com/search?q=%22lucidity+reactivation%22&type=repositories).
- Commercial devices expose no user-auditable event logs in the sources read; Hypnodyne offers EDF plus XML sleep reports and a scripting layer — [Hypnodyne](https://hypnodynecorp.com/zmax.php).

### Inferences
- Protocol fidelity features (seeded assignment, scheduler that can only schedule cued items, blind retest, descriptive cued-vs-uncued analysis) are absent from every open sleep-cueing codebase found; they exist only as lab procedure or in SMACC's experimenter console, which is manual and Windows-only.
- Structured machine-readable cue logs (play/skip/block-reason/volume) exist in COsleep and home-tmr, but both target NREM/N3 and have not been updated since 2023/2022.

### Gaps
- The exact event schema of SMACC's and COsleep's logs (JSONL vs text) was not inspected.
- Whether Dreamento's stimulation can be scripted into an automatic protocol was not verified.

## Key Question 5: Traction, maintenance and remaining gaps in open-source sleep cueing

### Takeaway
Traction is modest everywhere: the most-starred repos are openSleep/Dormio (~485 stars, stale), brain-eeg-graph (~312 stars, unfinished), awesome-lucid-dreams (~173), Dreamento (~152, last push March 2024), Halovision-INSPEC (~65, active), COsleep (~40, stale), home-tmr (~24, stale). The actively maintained projects in October 2026 are Portiloop software (spindles, research hardware), INSPEC (camera), SMACC (experimenter console) and one-week-old hobby CLAS repos; no open project combines a consumer EEG headband, real-time REM detection, closed-loop low-volume cueing, a randomized/blinded protocol and safety guards.

### Cited Findings
- Star/activity figures (GitHub, 2026-10-21): openSleep 485 stars, last push 2023-03-01; Dreamento 152 stars, last push 2024-03-18; awesome-lucid-dreams 173 stars, last push 2026-09-27; Halovision-INSPEC 65 stars, last push 2026-10-20; COsleep 40 stars, last push 2023-07-06; home-tmr 24 stars, last push 2022-12-07; brain-eeg-graph 312 stars, last push 2020-02-17; flicker 12 stars, last push 2019-07-10; rmallela26/TLR 7 stars, last push 2024-10-29; SMACC 2 stars, last push 2026-07-08; portiloop-software 6 stars, last push 2026-10-21; Taran-Douley/closed-loop-sleep 1 star, created 2026-10-06 — [GitHub search results](https://github.com/search?q=dreamento+OR+portiloop+OR+%22lucid+scribe%22&type=repositories) and repo pages linked above.
- Citations/validation: Portiloop has a PLoS ONE 2022 paper with MODA benchmark — [PMC9394839](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC9394839/); Dreamento has SoftwareX 2023 and a ZMax validation preprint — [GitHub](https://github.com/dreamento/dreamento); SleepStim has J Sleep Res 2022 with n=61+24 — [bioRxiv](https://www.biorxiv.org/content/10.1101/2022.06.28.497977v1); COsleep is registered as RRID SCR_017053 but lists no paper — [RRID](https://rrid.site/data/record/nlx_144509-1/SCR_017053/resolver/pdf&i=rrid:scr_017053); Lucid Scribe claims 20+ Scholar citations (self-reported) — [Product Hunt](https://www.producthunt.com/p/inspec-lucid-dreaming-device/inspec-lucid-dreaming-device).
- Portiloop status per Polytechnique Montréal: five prototypes, two in labs at Concordia and McGill, "not yet ready for bedroom use" — [Polytechnique](https://www.polymtl.ca/carrefour-actualite/node/5793).
- The Choi 2020 review found fewer than 10 reports on open-source libraries for closed-loop sleep systems — [PMC7285770](https://pmc.ncbi.nlm.nih.gov/articles/PMC7285770).
- Konkoly et al. explicitly name the missing piece: the app "couldn't detect REM sleep, so cues could be mistimed and disrupt sleep", and the lab has "begun working with InteraXon, the maker of the Muse-S headband" — [PsyPost](https://www.psypost.org/lucid-dreaming-app-triples-users-awareness-in-dreams-study-finds/); their paper records that cues raised movement-detected disruption (p=.002) and that intensity calibration at home is hard — [PMC11542932](https://pmc.ncbi.nlm.nih.gov/articles/PMC11542932).
- SleepStim showed that only low-intensity cues helped and high-intensity cues abolished the benefit, concluding "avoiding sleep disruption is critical" — [bioRxiv](https://www.biorxiv.org/content/10.1101/2022.06.28.497977v1).
- Mota-Rolim 2019: of ten lucid-dream devices only DreamLight has published empirical results; most lack independent validation — [PMC6517539](https://pmc.ncbi.nlm.nih.gov/articles/PMC6517539).
- Two other Muse-S-targeting hobby repos appeared in the same search: southsko/muse-sleep-dashboard ("Muse S EEG overnight sleep staging pipeline and dashboard", 1 star, last push 2026-10-03) and Taran-Douley/closed-loop-sleep (CLAS targeting Muse S Athena via BrainFlow, simulation-only) — [GitHub search](https://github.com/search?q=%22closed-loop%22+sleep+stimulation+EEG&type=repositories), [GitHub](https://github.com/Taran-Douley/closed-loop-sleep).

### Inferences
- Measured by maintained code that a home user could run tonight on a consumer headband with REM gating, the open field is empty: the two TLR apps are phone/watch timer- or HR-based, Dreamento needs a ZMax plus Windows HDServer and is not confirmed closed-loop, COsleep needs an OpenBCI rig under Linux and is stale, and Portiloop is research hardware for spindles.
- The literature's own stated failure modes for home cueing — mistimed cues without REM detection, over-loud cues causing arousals, uncalibrated intensity — map onto exactly the components (REM gate, arousal guard, volume calibration, cooldowns) that no open project bundles together; this is the defensible positioning claim for a Muse-S-Athena TLR engine.
- Northwestern's InteraXon collaboration is the most likely future competitor/complement; as of the sources read, nothing from it is public.

### Gaps
- No download or citation counts for Lucid Scribe, Dive or the Fitbit "Dream" app were available.
- Possible newer Portiloop publications (2024–2026) were not checked because the search budget ran out; the software repo was pushed on 2026-10-21, so the project is clearly alive.
- Reddit r/LucidDreaming and r/sleephackers DIY-device discussions were not surveyed (budget).
