# Initiative 10: Agreement analysis of Athena optics heart rate against Polar H10 ECG, with quality flags the arousal guard respects

## Why

The repository derives heart rate from the Athena forehead optics twice and validates neither. `muse_realtime_decoder.py` fills `HeartRateSample` from its own peak detector on optics channel index 0 (`LO_NIR`, an outer channel labelled fNIRS in `muse_athena_protocol.py` lines 89–94) over a 2–5 s buffer (lines 272–278, 306–334). `src/muse_tmr/features/ppg_features.py` estimates HR again per epoch from the channel with the largest variance (lines 320–331) and emits `ppg_confidence` (line 310) and `ppg_signal_quality` (lines 509–516), while `_sudden_hr_changes` (lines 437–461), the input to the guard's HR-jump rule, reads only the decoder stream. `ArousalGuard._collect_ppg_reasons` (`src/muse_tmr/protocol/arousal_guard.py` lines 344–373) reads the sudden-change counts, coverage and `artifact_flags`; nothing in `src/` or `scripts/` reads either quality field. The beat-level reference that `docs/validation.md` line 48 still calls missing is already recorded: `muse_tmr.data.polar_session` maps Polar H10 ECG R-peaks and RR onto the Muse wall clock (`PolarSession`, lines 262–271). Two source statements lose to the code: `calibration-run` defaults to `--preset p21`, which has no optics (`src/muse_tmr/cli/main.py` lines 694–700), so paired optics+ECG data needs `--preset p1034`, the app's `session` kind (`src/muse_tmr/app/server.py` lines 56–59) or `record --preset p1034 --with-polar`; and the `ppg_confidence` field the judgement asks to add already exists — only a consumer is missing.

A second defect was verified by running the code at `6593385`: `pilot3.py` (lines 228–236) and `pilot4.py` (lines 349–357) pass a `PPGFeatureRow` to the guard on every preset. On an EEG-only epoch that row carries `ppg_missing`, `heart_rate_missing`, `low_ppg_coverage`, `low_heart_rate_coverage`; the guard answers `lower_volume` twice and, from the third consecutive epoch, `pause` with `repeated_artifact_quality` (lines 200–222), which the scheduler turns into a ≥120 s pause (`tmr_scheduler.py` lines 254–285). Every `p21` night, the app's night-mode preset, is therefore guard-paused from the third epoch on. The gate has `optics_capable` for exactly this case (`src/muse_tmr/models/rem_gate.py` line 56, set via `preset_provides_optics` in `cli/main.py` lines 2008 and 2122); the guard has none, and no test covers it: `tests/test_pilot3_replay_simulation.py` line 75 and `tests/test_pilot4_cueing.py` line 353 both inject a synthetic `LO_NIR` pulse.

The literature treats PPG as corroboration and an arousal signal, not a REM fix: wrist devices reach REM sensitivity 67–83 % against PSG (Robbins et al. 2024, Sensors, Oura-funded, https://pmc.ncbi.nlm.nih.gov/articles/pmc11511193); the one EEG+PPG fusion study gained in light sleep, not REM (arXiv 2602.15042, 2026 preprint, https://arxiv.org/html/2602.15042) (both per notes/wearable_rem_physiology_open_science.md KQ4). No inspected open project has an ECG-referenced study for Athena: muse-monitor (https://github.com/LuanVanTran12395/muse-monitor) derives HR/HRV from the optics unvalidated and calls its ΔHbO "exploratory" (not re-verified); OpenMuse's roadmap still reads "validate the best PPG signal extraction method"; BrainFlow deliberately "does not convert these into synthetic PPG rows". The payoff for the REM core is modest, hence last place: nights run on `p21` for battery reasons (#108, `p1034` ≈23 %/h), so PPG is absent when it would matter. This issue measures HR/IBI agreement only: no SpO₂, no HbO/HbR, no stage claims, no efficacy.
