# Open-source ecosystem around InteraXon Muse headbands (Muse 2 / Muse S / Muse S Athena), state as of 2026-10-21

Scope note: this file covers every notable open-source (and the main closed) project that talks to a Muse headband or processes Muse data, so a writer can position `yuriy-mikityuk/remind-eeg` against them. remind-eeg itself is described only as the brief gave it (Python engine recording Muse S Athena overnight through a forked amused-py BLE layer, real-time REM detection, REM-gated audio cues for a TMR/TLR protocol, local web app) and is not evaluated here. Star counts, commit dates and "pushed_at" values come from the GitHub API (via the GitHub MCP repository search run on 2026-10-21) or from the GitHub repo page fetched the same day; treat all of them as approximate. Anything whose last push is before 2023 is marked STALE. The web-search budget ran out at the very end, so two small items (the official "Muse Data Portal", current status of the "Muse Direct" iOS app) are listed as gaps rather than guessed.

## Key question 1: What are the main Muse BLE/streaming libraries, and which support Muse S Athena (new BLE protocol, optics/fNIRS packets) in 2026?

### Takeaway
As of October 2026 there are four active open-source routes into a Muse S Athena: `muse-lsl` (Athena support merged June 2026, optics exposed since Sept 2026), BrainFlow (Athena board added in 5.22.0, dated May 2026 on brainflow.org), OpenMuse (Athena-only Python decoder with LSL, Sept 2025–Jan 2026 activity) and the Rust `muse-rs` (Oct 2026). `amused-py`, the library remind-eeg forks, was the first to publish the Athena BLE protocol (Aug 2025) but has had no PyPI release since 1.0.2 on 2025-08-24 and only 25 commits; none of these libraries computes fNIRS (HbO/HbR) from the raw optics, and none offers overnight recording, sleep staging or cueing.

### Inferences
- Athena support arrived in waves: community reverse engineering (AbosaSzakal parser; amused-py Aug 2025; OpenMuse Sept 2025) → BrainFlow (May 2026) → muse-lsl (June–Sept 2026) → muse-rs (2026). By October 2026 Athena EEG/IMU/optics streaming is a solved problem in at least four libraries, so "talks to Athena" is no longer a differentiator; "does something with the data overnight" is.
- fNIRS is universally raw-only: every library exposes optics counts, and the two most-cited maintainers (OpenMuse, muse-lsl) explicitly decline to compute HbO/HbR for lack of validated geometry/wavelength info. Any project that validates fNIRS extraction or even just HR/HRV from Athena optics would fill a real gap.
- amused-py, remind-eeg's upstream, looks like a one-shot release (three PyPI versions in four minutes, 25 commits, no release since 2025-08-24, undocumented sleep client files). A fork that keeps the BLE layer alive and tested is therefore carrying real maintenance burden, and the fork's divergence from a dormant upstream should be documented (remind-eeg's own docs apparently do this in `docs/dependency_strategy.md`, per its AGENTS.md).
- Of the general libraries, only amused-py offers a replay player and only OpenMuse/muse-lsl/BrainFlow/BlueMuse offer LSL; none bundles recording-for-hours, so sleep projects on Muse (see Q2) always add their own recorder or rely on Mind Monitor CSV.

### Gaps
- Exact year of BrainFlow 5.22.0: the GitHub releases UI omits years; brainflow.org's slug says 2026-05-08, while a secondary summary of muse-lsl #222 implies BrainFlow Athena support existed in Aug 2025. I could not open BrainFlow issue #804 to settle it.
- Last-commit dates for amused-py and OpenMuse come only from the GitHub API `updated_at`/`pushed_at` fields; I did not inspect commit logs.
- I did not find any independent benchmark of timestamp accuracy or packet loss across amused-py / OpenMuse / BrainFlow / muse-lsl on Athena (OpenMuse lists timestamp validation as an open roadmap item).
- Mind Monitor's own website (mind-monitor.com) returned HTTP 403, so its OSC spec and any Athena optics support were not verified beyond the App Store text.

## Key question 2: Are there open-source projects that do overnight sleep recording, REM detection or sleep staging on Muse data?

### Takeaway
Yes, but all are tiny (≤2 stars), very recent (Sept–Oct 2026) or abandoned: the only Muse sleep-staging pipeline found is `southsko/muse-sleep-dashboard` (Athena → OpenMuse on a Raspberry Pi → offline YASA staging; no real-time, no REM-specific logic), plus `Oleksandr-Nyemtsev/NeuroTrainer` (Sleep-EDF-trained CNN, Muse 2, real-time loop "still in development") and an archived 2019–2022 JavaScript "Muse sleep tracker + Arduino light therapy". There is no open-source real-time REM detector validated on Muse; the only Muse sleep dataset is InteraXon's own 540-recording sleep-onset set (CC-BY-NC-SA, N2-onset label only) released for a 2026 challenge.

### Inferences
- Unique territory for a maintained open project on Athena, by elimination of what exists: (1) hours-long BLE recording with deterministic replay and tests that run without hardware; (2) a REM detector with explicit P_REM, reason codes, manual annotation + personal retraining, and a stable gate separate from audio; (3) REM-gated cue scheduling with arousal guard, volume calibration, emergency stop and structured cue logs; (4) cued-vs-uncued randomization and morning blind retest for TMR/TLR; (5) a published validation plan with limitations instead of efficacy claims. Everything in the brief's one-paragraph description of remind-eeg maps onto these gaps; the project's distinct risk is depending on a dormant upstream BLE layer (amused-py) while muse-lsl/BrainFlow/OpenMuse now also speak Athena.
- Where remind-eeg does *not* stand out (per the brief and this survey): raw Athena streaming, LSL bridging and visualization are better served by muse-lsl, OpenMuse and BrainFlow (larger communities, multi-OS CI). An LSL/OpenMuse input adapter (which remind-eeg's AGENTS.md says exists) is the sensible way to inherit that work instead of competing with it.
- Validated PPG-HR/HRV and fNIRS from Athena optics is a gap shared by every project, including vendors' third parties; whoever publishes a validated extraction (e.g., against a Polar H10 or finger PPG) would become the reference implementation.
