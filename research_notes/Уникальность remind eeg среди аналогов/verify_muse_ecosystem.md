## Technically true but misleading in context

1. **BrainFlow "MIT"** (table row and Q1 bullet). The LICENSE is MIT, but it carries an "IMPORTANT NOTICE" forbidding extraction, modification, sublicensing or redistribution of the bundled SimpleBLE component (owned by The California Open Source Company LLC); GitHub classifies the license as "Other". A project that vendors or forks BrainFlow's BLE layer is bound by that notice. The notes' "all features available for free and distributed under MIT license" is BrainFlow's own README wording.
2. **muse-lsl #237 "quote"**. The notes put "muse-lsl does not compute derived fNIRS values such as HbO and HbR" in quotation marks; the maintainer actually wrote "we don't currently compute those in muse-lsl" and "Reliable conversion requires wavelength and source–detector metadata that we don't currently have." The substance is the same, but the report must not attribute the notes' sentence verbatim. Same for OpenMuse #23: actual wording is "is not open afaik", not "does not appear to be open".
3. **"Optics exposed since Sept 2026" (Q1 Takeaway)**. muse-lsl exposed Athena optics in June 2026 (PR #228); September 2026 added only the `--ppg` alias and PPG LSL type (row 2).
4. **amused-py "one-shot release"/"dormant upstream" (Q1 Inferences, Q5 Inferences)**. True for PyPI (1.0.2 is the last release), false for the repository: a protocol-correcting rewrite landed 2026-03-16 and a fix PR 2026-04-23 (row 5). The "divergence from a dormant upstream" risk is real but six months old, not fourteen, and the more relevant fact is that PyPI 1.0.2 ships a decoder upstream itself later replaced as "correct Athena BLE protocol".
5. **Lucid Scribe's "only REM-detecting device that is available" (Q3 Takeaway/Inferences)**. This is a sales banner on lucidcode.com linking to its own device comparison; lucidcode sells the INSPEC camera. It is a vendor statement about hardware for sale, not an assessment of software projects, and should not be cited as evidence that Muse users "have no maintained lucid-dream cueing tool outside remind-eeg".
6. **NeuroTrainer "~79% accuracy / macro-F1 ~0.74 on Sleep-EDF"**. The README labels these interim numbers "on an intermediate dataset" and "a research result, not clinical validation" (row 10). Do not present them as a validated baseline.
7. **Dream Recall vs Smart Wakeup (Q4 Takeaway lists them as separate features)**. Gadgets & Wearables says Dream Recall is in beta "as part of Smart Wakeup for Muse Premium subscribers using a Muse S or Muse S Athena"; it is a Smart Wakeup mode, not a separate product.
8. **nm000287 "500 train / 40 test (test participants also in train)"**. Correct, but the dataset README itself says the split "evaluates new recordings from known participants, not generalization to unseen people" — any accuracy quoted from the 2026 challenge is subject-dependent.
9. **BrainFlow Athena support "settled since May 2026"**. PR titles #855 "Fix Muse S Athena EEG scale factor" and #856 "Center Muse S Athena EEG samples around zero" (merged 2026-08-18, shipped in 5.23.0 on 26 Sep 2026) indicate that 5.22.x Athena EEG amplitudes were mis-scaled; only PR titles were read, not the diffs.
10. **BrainFlow 5.22.2 "Fix Muse Athena macOS reconnect hangs (#837)"**. The notes cite this fix without noting that PR #837 was authored by **yuriy-mikityuk**, the owner of remind-eeg (merged 2026-05-21). For a positioning report this matters: remind-eeg's author contributes Athena fixes upstream to BrainFlow, and `docs/dependency_strategy.md` mentions a BrainFlow fork for Athena prototyping.
11. **Q2 Takeaway "very recent (Sept–Oct 2026)"**: muse-sleep-dashboard dates from July 2026 (row 9); NeuroTrainer from 2026-09-19; closed-loop-sleep from 2026-10-06.
12. **SLEEP Advances "16% excluded"**: derived from "47 (84%)" in the abstract; the abstract does not state 16% or the exclusion reasons.
