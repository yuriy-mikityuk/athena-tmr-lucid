# REMind: adoption-and-community strategy (state as of 2026-10-21, HEAD `1765041`)

Scope: eight prioritized initiatives that would make `yuriy-mikityuk/remind-eeg` the default open platform people *build on* for sleep-time cueing with consumer EEG, judged on adoption and community only: positioning against muse-lsl / OpenMuse / BrainFlow / Dreamento, PyPI release, docs site, standard formats, plugin points, a benchmark results table, synthetic test fixtures, governance, roadmap, and the trust pattern of Portiloop, Dreamento and YASA. Every proposal was checked against the checkout (`1765041` = the inventory's `88df221` plus commits that add only `research_notes/*`; `git rev-list --left-right --count origin/main...HEAD` = `0 4`, no code differs) so nothing already implemented is proposed again; where an initiative builds on existing code the "Extends" line names the modules. Corrections in the `verify_*.md` files override the original notes throughout. Two sibling documents cover other lenses and are cross-referenced, not repeated: `strategy_technical.md` [ST] (engineering differentiation) and `strategy_science.md` [SC] (scientific credibility). No initiative below promises lucid-dreaming, memory or clinical efficacy; the repository's `docs/validation.md` "Reporting Language" rules apply to every artefact proposed.

Source legend (all files in this folder): [RI] `repo_inventory.md`, [VRI] `verify_repo_inventory.md`, [CT] `cueing_tools_landscape.md`, [VCT] `verify_cueing_tools_landscape.md`, [ME] `muse_ecosystem.md`, [VME] `verify_muse_ecosystem.md`, [SS] `sleep_staging_tools.md`, [VSS] `verify_sleep_staging_tools.md`, [TS] `tmr_tlr_science.md`, [VTS] `verify_tmr_tlr_science.md`, [WR] `wearable_rem_physiology_open_science.md`, [VWR] `verify_wearable_rem_physiology_open_science.md`, [G1] `gap_1_direct_open_source_competitor_softcoding.md`, [G2] `gap_2_the_repo_s_only_accuracy_figures_live_so.md`, [G3] `gap_3_status_of_northwestern_interaxon_muse_tl.md`, [G4] `gap_4_the_ocular_channel_on_muse_why_the_eye_m.md` (pointer `gap_ocular_channel.md`), [local] = re-checked on this checkout on 2026-10-21 with `ls`/`grep`/`sed`.

## 1. Where the repository stands for a newcomer

What exists (do not rebuild):

- A complete, unit-tested engine: BLE source → recorder/replay → `EpochBuilder` → EEG/IMU/PPG features → heuristic REM detector / personal logistic classifier → `StableRemGate` → `ArousalGuard` → `TmrCueScheduler` → `AudioCuePlayer`, plus puzzle protocol, seeded cued/uncued assignment with structurally unschedulable controls, TLR training/block plan, dream report, blind retest, cued-vs-uncued analysis, five pilot validators, a local web app, Polar H10 companion, meditation side track; 60 test files, 706 `def test_` functions; a four-job CI (`policy`, `tests`, `package` with wheel build + `scripts/check_wheel.py`, `page` in headless Chrome) on Ubuntu / Python 3.11 only [RI Q0–Q1, VRI A2/A4].
- Governance that is unusual for the field: `AGENTS.md` (17 KB of rules for people and coding agents: git preflight, one issue per change, no private data or SDK files, conservative audio, no efficacy claims), `docs/agent_rules.md` as its summary, a README "Contributing" section pointing at both, a CI `policy` job running `scripts/check_forbidden_files.py`, a `CHANGELOG.md`, three tagged GitHub releases (v0.1.0–v0.3.0, all 2026-10-19), MIT licence whose copyright line names only the upstream amused-py author [VRI A15/B2/B9; local].
- Twenty Markdown docs (USAGE 573 lines, data_model 478, five pilot runbooks, architecture, safety, validation, sdk_policy, dependency_strategy) [VRI B9]; `pyproject.toml` has `[project.urls]` (Homepage, Documentation → `docs/USAGE.md`, Repository) and a `docs` extra (sphinx, sphinx-rtd-theme, autodoc-typehints) that builds nothing because there is no `docs/conf.py` [VRI B2; local].
- Extension seams: `BaseMuseSource` (discover/connect/stream/stop) with amused, OpenMuse-LSL, BrainFlow and a policy-only SDK stub; `OpenMuseLslSourceConfig.stream_names` is configurable in code but defaults to OpenMuse's `Muse_EEG`/`Muse_ACCGYRO`/... names and is not exposed on the CLI; `create_audio_backend()` and every `--source`/`--backend` CLI argument hard-code their choice lists (`amused|brainflow|openmuse|sdk`, `system|afplay|dry-run|mock`) in at least six parsers; no entry points or registry anywhere in `src/muse_tmr` [RI Q2; local grep].
- Fixtures: one 28,122-byte recorded raw fixture from the upstream era (2025-08-24, awake), used by `test_integration`, `test_minimal`, `test_raw_stream`; seven contact-quality JSONL scenarios; a `write_synthetic_recording()` helper duplicated in `test_replay.py`, `test_pilot3_replay_simulation.py` and `test_rem_annotations.py` that writes zero-filled TAG packets (`bytes(28)`, `bytes(36)`, `bytes(60)`) — format-valid, physiologically empty; a `build_rem_epoch()` feature-row helper in the Pilot 3 test; the app's `--source mock` lives inside `app/server.py` [VRI A16; local].
- Replay reads only `raw_amused.bin` (`resolve_raw_path`); `decoded_frames.jsonl` (the raw artefact for BrainFlow and other non-raw sources since #108) "has no replay/feature-extraction path yet" [G2 A3c/A3d; local].

What is absent [local; G2 A6c/A7; VRI]: a PyPI release (HTTP 404 for `athena-tmr-lucid`, `muse-tmr`, `remind-eeg`, `muse_tmr`), `CITATION.cff`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`, a roadmap file, issue or PR templates (`.github/` holds only `workflows/guardrails.yml`), GitHub Discussions (disabled), labels beyond GitHub's nine defaults (priorities P1/P3 live in comment text), a documentation site, a CI matrix (3.11 only while `requires-python >=3.8` is declared), EDF/BIDS import or export. The wheel ships 16 top-level `py-modules` (`amused`, `muse_*`) next to the `muse_tmr` package [VRI B2; local], and the distribution is still named `athena-tmr-lucid` although the repository was renamed `remind-eeg` (the one public fork, `webbrain-one/athena-tmr-lucid`, keeps the old name) [G2].

Community signals: 7 stars (one is the owner's), 1 fork, 1 external issue (#167, answered within a week and triaged P3), two git identities both the owner, bus factor 1 [G2 A4/A6c; RI Q8]. The accuracy figures a newcomer will ask about (κ 0.30, precision 0.30 at recall 0.80, 342/959 gate-open epochs, the per-feature AUC table) exist only in PR #115 and issue #116, from one EEG-only night scored against GSSC with thresholds fitted on that same night; `presets.py` and README say "VALIDATED" where "tuned in-sample against an automated proxy" is correct; no audio night has ever been run (the EPIC's v0.3.0 tracking block: "No live BLE or sleep-time audio run was part of this update") [VRI A6/C1; G2 A6b/A6e].

The sleep layer above streaming is thin: offline YASA staging (southsko/muse-sleep-dashboard, 1★, no licence, smoke test only), an open NREM slow-oscillation TMR tool that does run on Muse through an external OSC stream (SoftcodingForYou/EazzZyLearn_pc, MIT, no tests/CI/packaging, last push 2025-11-04, REM probability received but never acted on) [G1], a simulation-only NREM CLAS for Athena (Taran-Douley, 1★) [VCT row 9], Dreamento (152★, MIT, SoftwareX 2023, ZMax-only, Python 3.6/TensorFlow 1.13.1, not on PyPI, unpushed since 2024-03-18) [VCT row 1], Portiloop (PLoS ONE 2022, open hardware, 6★, no licence file, pushed 2026-10-21) [VCT row 3], SMACC (GPL-3, Windows, experimenter console), COsleep and home-tmr (stale since 2023/2022). Two Muse + lucid-dreaming repositories predate REMind (lucidcode's 2015 plugin, Venryx/LucidLink 2016–2020), both stale and neither REM-gated [VME row 15]. The vendor ships REM-timed *waking* (Dream Recall, a Smart Wakeup mode) and closed "programmable TMR" for vetted research partners, with no public real-time REM event API [G3 KQ4–KQ6]. The trust pattern of the small projects that gained traction is: permissive licence + a quantitative validation published in PLoS ONE / SoftwareX / eLife / JOSS + open datasets or benchmark reuse + (increasingly) preregistration; uninstallable packaging (ezscore-f in an independent 2026 evaluation) and undisclosed training data (Hypnodyne ZLab) are explicitly penalised [WR KQ8]. No live sleep-staging leaderboard exists; SleepYland, Stanford Sleep Bench and SleepBench are offline PSG evaluation frameworks [WR KQ8]. Open headband+PSG data exist (BOAS: CC0, BIDS, 128 nights/100 people, Ikon AF7/AF8 at 256 Hz + IMU + pulse; DOD: MIT; Wearanize+: DUA) but no public Muse overnight dataset [VSS row 14; VWR rows 12–13/18]. A demand signal: a Mind Monitor forum question on turning Muse CSV into EDF for YASA sits unanswered [ME Q2].

### Initiative 1 — Position REMind as the protocol-and-safety layer above any Muse streamer, and say so where newcomers land

**Extends:** `README.md` (opens "REM/TMR/TLR engine for Muse S Athena (Konkoly-like protocol)"), `docs/architecture.md`, `docs/dependency_strategy.md`, GitHub topics and `pyproject` metadata. No engine code.

**Build (issue-ready):**
1. README first screen: one-sentence definition — "an open, REM-gated, arousal-guarded, randomised cue-scheduling engine with structured JSONL logs; it takes Muse frames from the bundled amused-py BLE layer, from OpenMuse over LSL or from BrainFlow" — followed by a dated "Project status" block with the numbers and their provenance: one EEG-only night (`overnight_20260707`), GSSC as an automated proxy (not PSG), thresholds fitted in-sample, zero completed audio nights, detector effectively one feature with a saturated eye proxy (#116), n = 1. Replace "VALIDATED" in `presets.py`, README line 127 and `docs/USAGE.md` with "tuned in-sample on one EEG-only night against GSSC" (SC #2 item 6 proposes the same wording fix; it belongs with positioning because it is the first thing a researcher checks).
2. Replace "Konkoly-like"/"Konkoly-style" with a plain description (pre-sleep cue pairing, REM-timed replay, one-way, no eye-signal verification) and cite the papers — SC #6 covers the citation list; here only the README claim changes.
3. `docs/compare.md`: a dated table of the repositories inspected in the notes — streaming (muse-lsl, OpenMuse, BrainFlow, BlueMuse, muse-rs, amused-py), offline staging (YASA, U-Sleep, GSSC, ezscore-f, southsko), ZMax dream engineering (Dreamento), NREM closed loop (EazzZyLearn_pc, Taran-Douley, COsleep, Portiloop), watch-based TLR (home-tmr, rmallela26/TLR), vendor features (Dream Recall as a REM-timed alarm) — with licence, OS, last push, what REMind adds (gate, guard, calibration, randomisation, blind retest, validators, replay) and what it does not do (streaming viewer, NREM CLAS, fNIRS, eye-signal detection). Wording "of the repositories inspected", never "only"/"first" [VCT item 3; VME row 15].
4. Make the upstream-first policy explicit in `docs/dependency_strategy.md`: BLE/protocol fixes go to amused-py, BrainFlow or OpenMuse first (as with BrainFlow PR #837 by the owner), the fork tracks and documents its divergence (midscale centering was added in the fork) and is meant to shrink [VME item 10; G4 A; ST §3].
5. Metadata hygiene: one upstream URL (pyproject pins `Amused-EEG/amused-py`, README and `docs/amused_upstream.md` link `nexon33/amused`), topics `targeted-memory-reactivation`, `closed-loop`, `muse-s-athena`, `Documentation` URL pointing at the site of Initiative 6 [VRI A15].

**Evidence:** "By October 2026 Athena EEG/IMU/optics streaming is a solved problem in at least four libraries, so 'talks to Athena' is no longer a differentiator; 'does something with the data overnight' is" [ME Q1 inference]; the corrected positioning sentence that survives verification is about openness, non-waking cueing, protocol controls and auditable logs, not REM-detection capability [G3 KQ6]; the categorical "no open-source TMR project uses Muse" is false (EazzZyLearn_pc) and must be replaced [G1 Inferences; VSS row 15]; LucidLink and the LucidScribe Muse plugin predate REMind as Muse + lucid-dreaming repositories [VME row 15]; "VALIDATED" is in-sample tuning [VRI C1]; no citation of Konkoly 2021 or Carr 2020 exists anywhere in the repository [VRI A12]; transparency is rewarded and undisclosed training data penalised in independent evaluations [WR KQ8]; the tracker's "honest, numeric self-assessment of detector weakness" is named as a distinctive strength [RI Q10 inference].

**Why no comparable open project has it:** Dreamento positions itself as a dream-engineering toolbox but is bound to ZMax, Windows and Hypnodyne's HDServer, and documents neither a competitor comparison nor its stimulation–stage coupling [VCT row 1]; EazzZyLearn_pc has an OSC input that is in principle hardware-agnostic but a partly stale, partly LLM-generated README with no status or comparison [G1 §0/§5]; no Muse project describes a hardware-agnostic protocol-layer role; the vendor describes Dream Recall as an alarm [G3 KQ4].

**Effort:** small — two documentation PRs.

**Risk / caveat:** a comparison table ages in weeks (star counts, push dates) and must carry its date and link the verified notes; naming competitors invites corrections, which is acceptable; an honest status block will deter people looking for a product — that is the intended filter; every "unique" claim must be scoped to the repositories inspected.

### Initiative 3 — A versioned, labelled synthetic night corpus in Muse formats

**Extends:** the three test-local `write_synthetic_recording()` helpers (zero-filled packets), `tests/test_data/muse_20250824_172756.bin`, `tests/fixtures/contact/*.jsonl`, `build_rem_epoch()` in the Pilot 3 test, the app `mock` source in `app/server.py`, `MuseRawStream.write_packet`, the TAG encoders in `muse_athena_protocol.py`, `ReplaySession`.

**Build (issue-ready):**
1. `muse_tmr.testing.synthetic`: a seeded generator driven by a scripted hypnogram (default 8 h, 4–5 REM periods, N1/N2/N3, wake bouts) that emits TAG_EEG_4CH / ACCGYRO / OPTICS packets with stage-typical content — 1/f background at 10–20 µV RMS; delta in N3; theta with low alpha in REM plus bipolar, opposite-polarity AF7/AF8 deflections of 20–60 µV and 0.3–1.5 s; alpha and blinks in wake — IMU bursts at arousals and position changes, PPG pulse at a scripted heart rate, the ≈63.9 Hz optics line at 20–40 µV on AF7/AF8 whenever an optics preset is active, BLE gaps, repeated and lost subpackets as in #160, battery decay; writes `raw_amused.bin`, `metadata.json`, `events.jsonl`, plus ground truth `hypnogram.csv`, `arousals.csv` and `generation.json` (seed, parameters, generator version).
2. A scenario library generated on the fly in CI (each ≤ 10 MB; a few pre-rendered on a GitHub release or Zenodo as `remind-synthetic-nights-v1`): `clean_night`, `fragmented_rem`, `no_rem_nap` (the only real optics night was a 0-REM nap), `battery_death_2h29` (#108), `optics_line`, `bad_contact_af7`, `movement_heavy`, `short_allow_short`.
3. Replace the duplicated test helpers with the generator; add a CI end-to-end job: Pilot 1 validator passes on `clean_night`, Pilot 3 simulation shows zero uncued `play`, the nightly HTML report renders, and the detector's agreement with the *generated* hypnogram is tracked as a regression number — explicitly not a validity claim. The fixture spec in [G4 A] (biphasic deflections on 1/f noise with a 40 µV line) would have caught the saturated eye proxy.
4. `docs/synthetic_data.md`: what is and is not modelled; every report produced from synthetic input carries the line "synthetic input, not sleep".
5. Offer the corpus to neighbours as a decoder test oracle: it is written in the Athena TAG format, so amused-py, OpenMuse, BrainFlow and muse-rs can decode it and compare against the ground truth.

**Evidence:** `AGENTS.md` prefers deterministic replay and synthetic fixtures before live BLE and forbids committing real nights [RI Q8]; the existing helpers synthesise format-valid but empty packets [VRI A16; local]; no public Muse overnight dataset exists on Zenodo, PhysioNet, OpenNeuro or the web [VWR row 18]; southsko's four synthetic recordings "prove code paths only, not real sleep quality" [ME Q2]; muse-monitor commits a golden raw Athena capture for tests [ME Q1]; Taran-Douley's only validation is a Sleep-EDF simulation whose latency "numbers are assumptions until measured" [VCT row 9]; the realism parameters come from the repository's own findings — 23.34 %/h optics drain and a 2 h 29 min death [G2 A3a/A3b], 43 repeated and 1 % lost EEG subpackets with a true rate ≈257.2 Hz [G2 A3f], the 63.9 Hz line of up to ~40 µV [G4 A] — and from the ZMax REM-event morphology on the equivalent F7/F8-to-Fpz montage [VWR row 6].

**Why no comparable open project has it:** none of the inspected Muse projects ships a labelled synthetic overnight corpus in device format; southsko's smoke recordings are unlabelled code-path checks; Taran-Douley simulates on PSG, not headband packets; Dreamento has no simulator; EazzZyLearn's simulator re-streams a user's own CSV over OSC in wall-clock time [G1 §6].

**Effort:** medium — signal synthesis about a week, scenario library + CI job + docs another; keep artefacts small.

**Risk / caveat:** synthetic agreement will be misread as validation unless every artefact is labelled; the generator encodes the author's assumptions about REM morphology on Fpz-referenced frontal channels (attenuated and over-counted on real headbands — [VWR row 6/G]), so a detector tuned on it can overfit the simulator; the corpus must never include fragments of real nights without an explicit consent decision.

### Initiative 4 — "Bring your own night": import adapters and a generic LSL input

**Extends:** `ReplaySession` (reads only `raw_amused.bin`), the `decoded_frames.jsonl` writer (no replay path, #108), `OpenMuseLslSourceConfig.stream_names` (configurable in code, OpenMuse defaults, not on the CLI), `frame_from_decoded`, `scripts/generate_nightly_report.py`, `simulate-replay-cues`, `annotate-template`. Complements the *export* proposals in ST #4 and SC #3; this is import.

**Build (issue-ready):**
1. `muse-tmr import <file> --format {muselsl-csv, mindmonitor-csv, openmuse-csv, openmuse-xdf, brainflow-csv, edf, decoded-frames}` → a recording directory with `decoded_frames.jsonl` + `metadata.json` (`source.source_name = "import:<format>"`, scale and offset applied and recorded), after which `replay`, the HTML report, `annotate-template`, `simulate-replay-cues` and `validate_rem_detection.py` work unchanged. The `edf` path gives BOAS headband files and ZMax EDFs a route into the pipeline (shared loader with SC #1 / ST #2 and Initiative 8).
2. A per-format unit/scale table with provenance, enforced: OpenMuse decodes without midscale centering (≈725 µV pedestal); BrainFlow before 5.23.0 scaled Athena EEG ≈4.55× too large and uncentred (PRs #855/#856); Mind Monitor units are unverified (the forum question about units is unanswered); the detector refuses to run unless the scale is declared (`--eeg-scale` or a format preset) and the report prints it [G4 A; ME Q2].
3. Generic LSL: expose `--lsl-stream-name` / `--lsl-stream-type` so `muselsl stream`, BlueMuse and OpenMuse all feed the live gate without the bundled BLE layer, and record `decoded_frames.jsonl` as the raw artefact for non-raw sources (as BrainFlow does since #108).
4. `docs/import.md`: a matrix of what each format loses (no raw packets, no sequence dedup, which clock the timestamps come from) and which validators apply — Pilot 1 requires `raw_packet_count > 0`, so imported nights are report-and-simulation only, never a pilot pass.

**Effort:** medium — the parsers are small; scale provenance, timestamp reconstruction, gap handling and tests per format are the work; XDF needs an optional `pyxdf` extra.

**Risk / caveat:** imported nights lack raw packets, dedup and gap accounting, so quality flags differ from BLE nights; the current detector (one effective feature, saturated eye proxy, thresholds tuned on one night) will produce P_REM traces on arbitrary nights that people will over-interpret — the report must carry the status block of Initiative 1; third-party timestamps drift (Wearanize+ lost nights to drift) [VWR row 13]; no cueing from imported data, replay and simulation only.

## 3. What the repository should not try to compete on

Raw Athena streaming, LSL bridging and live visualisation are solved by larger, multi-OS-tested projects — muse-lsl (781★, BSD-3, Athena since June 2026), BrainFlow (1.8k★, seven CI badges, Athena since May 2026, with the owner already contributing fixes upstream), OpenMuse, muse-rs, BlueMuse — so REMind should keep its adapters current, send protocol fixes upstream first and let the forked amused-py layer shrink rather than grow [VME rows 1–8, item 10]. General-purpose sleep staging cannot be out-trained by one author against YASA, U-Sleep, GSSC or SleepFM, which were trained on thousands to tens of thousands of PSG nights; they are references and baselines (Initiative 8), and the in-house detector stays a small, causal, explainable REM component [SS KQ1; G2 Part B]. NREM slow-oscillation phase-locked stimulation is an occupied field (EazzZyLearn_pc, Taran-Douley, COsleep, Portiloop, Dreem/Beacon, FRENZ, Elemind, SleepLoop, Philips) with sub-150 ms latency needs that a 30-s-epoch BLE pipeline is not built for [CT KQ1/KQ3; G1; VTS spot check]. fNIRS HbO/HbR from Athena optics is declined by every maintainer for lack of validated wavelength and geometry data and has no 2021–2026 REM or arousal study behind it [VME rows 3–4; WR KQ5]. REM-detection superiority over the vendor is not a credible goal: InteraXon's closed model reached REM κ 0.85 on Muse-S in an independent lab study and ships REM-timed waking and research TMR; REMind's claim is open code, non-waking REM-gated cueing, protocol controls and auditable logs [VWR row 1; G3 KQ6]. Automatic eye-signal (LRLR) detection and two-way dream communication have no algorithm with a reported sensitivity or false-positive rate in the 2021–Oct 2026 literature; every verification was human-rated under PSG — ship LRLR-ready logging, not detection [G4 B]. Stars are a weak signal in this niche: the most-starred hobby repositories (openSleep 485★, brain-eeg-graph 312★) are stale or unfinished [CT KQ5], so adoption should be measured by installs, imported nights, external PRs and citations, and never by telemetry, which `AGENTS.md` forbids. "First" and "only" claims should be dropped: LucidLink and the LucidScribe Muse plugin predate REMind, EazzZyLearn runs TMR on Muse, and the correct wording is "of the repositories inspected" [VME row 15; G1; VCT item 3]. Consumer app polish, app-store distribution, cloud sync, multi-user accounts and telemetry are outside the n = 1 research scope and partly forbidden by the repository's own rules [RI Q0/Q10]. Finally, the repository should not compete on efficacy of any kind — lucid-dream induction, memory or clinical outcomes — because the best-controlled recent studies are modest or null (Hu 2020 REM g = −0.06; Picard-Deland 2024 preprint induction not different from sham; Konkoly 2026 no overall cueing effect; Konkoly 2024 home cues raised movement events and the arousal explanation could not be ruled out) [TS KQ1–KQ3; VTS rows 4/7/8]; its community value is being the open, installable, auditable platform on which such questions can be asked.
