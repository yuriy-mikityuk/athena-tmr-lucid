# Verification of cueing_tools_landscape.md (adversarial fact-check, 2026-10-21)

This file confirms or corrects the factual claims in `cueing_tools_landscape.md` (same folder). Every row below was checked against the source the notes cite, or against the GitHub API (via the GitHub MCP repository search) on 2026-10-21. **The report writer must prefer the statements in the "Corrected statement / notes" column over the original notes wherever the verdict is CORRECTED, must use the re-attributed sources where a row says the notes' citation does not support the claim, and must carry the caveats listed under "Technically true but misleading in context".** The original notes file was not edited.

Method: 16 consequential claims were selected (star counts and push dates, sample sizes and effect figures, journal attributions, and "no open project does X" statements). Each was checked by fetching the cited URL (PMC, bioRxiv, Crossref/DataCite/OpenAlex metadata, raw GitHub READMEs, prophetic.com, the App Store, hypnodynecorp.com, Sleep Review, MedTech Dive, MIT News) or by querying the GitHub API. WebSearch was used twice, only for the Dreem/Beacon timeline whose cited articles did not contain the claim. Six further claims were spot-checked and are listed at the end. Star counts are point-in-time values. Commit counts quoted in the notes (Dreamento 148, INSPEC 420, Taran-Douley 12, COsleep 42, openSleep 189) were not re-counted except where a repo page was fetched (rmallela26/TLR 5, SMACC 200).

Summary: 16 claims checked — 14 CONFIRMED, 2 CORRECTED, 0 UNVERIFIED. Neither correction overturns a conclusion of the notes; the items most likely to mislead a reader are the categorical "only/none" statements listed in the misleading section (items 1–3), which the report should soften rather than repeat verbatim.

## Technically true but misleading in context

1. **"The only open project that both targets REM and ships a staging model is rmallela26/TLR" (Q1 Inferences).** Defensible only under a narrow reading ("an open *app* that bundles a sleep-staging classifier producing REM labels from a consumer wearable and times cues to it"). Counter-examples a reader will raise: lucidcode/Halovision-INSPEC is open firmware that detects REM from eye-area video and triggers cues automatically, and was pushed 2026-10-20 (65 stars); Dreamento ships a staging model (DreamentoScorer) and real-time stimulation, only the stage→stimulus coupling is undocumented; the LucidScribe ThinkGear/OpenEEG plugins (2012–2022) advertise "triggers audio tracks when rapid eye movement patterns are detected". The report should say "the only open *sleep-staging-based* REM-cueing app on a consumer wearable" and name INSPEC (video) and Dreamento (EEG, coupling undocumented) as the nearest neighbours.
2. **"GitHub search for 'closed-loop sleep stimulation EEG' returned only two repos" (Q1 and Q5).** True for that exact query (re-run 2026-10-21: IVeuromancer/SleepScoring and Taran-Douley/closed-loop-sleep). But `"closed-loop auditory stimulation" sleep` returns three more: HHebron/aclas_PB ("Data and scripts for the paper: A closed-loop auditory stimulation approach selectively modulates alpha oscillations and sleep onset dynamics", MATLAB, 1 star, 2024), emjen7/Validating-a-Novel-Sleep-Measuring-Device-and-Closed-Loop-Auditory-Stimulation (PhD appendices, 2026) and jasonjiao2024/tsle-sleep-simulation (model study, 2026). None is a cueing engine, so the conclusion stands, but the "only two repos" figure is a query artefact and should not be quoted as a census. Related: the notes say of Hebron et al. 2024 "no open-source library named" — correct, but the paper's data and analysis scripts are on GitHub (HHebron/aclas_PB).
3. **"No open project found implements seeded cued-vs-uncued item randomization plus blind morning retest plus analysis inside the software" (Q4 Takeaway) and "Protocol fidelity features ... are absent from every open sleep-cueing codebase found".** Nothing checked contradicts this, and the READMEs of COsleep, home-tmr, Dreamento, Portiloop and Taran-Douley confirm the absence (COsleep has sham/stim *blinding* only; home-tmr has a spatial task but no randomization code; Taran-Douley lists sham nights as unimplemented). The caveat is scope: the GitHub "targeted memory reactivation" query returns 18 repositories today (re-run), including a few not in the notes (riapap1982/project-insomnia-, an HTML "TMR app for sleep learning", 2026-08; albertorsesc/soundmind, 2 stars; adriandelser/tmr_study; Hesam-lab/sleep-tmr-eeg-analysis) — all tiny and none inspected for randomization logic. State the claim as "none of the N repositories inspected", not as an absolute.
4. **Konkoly 2024 cue description (Q2).** The 400/600/800 Hz beeps and 1000-ms violin were the Experiment 1 cues; the randomized, participant-blind Experiment 2 — the one the notes rely on as "the only published blinded, randomized home TLR protocol" — used two ~3-s harp melodies with fade-in/out. A recommendation to adopt "the Konkoly cue" must say which experiment it means. The three-rising-tone spec is separately documented in the NCT05709873 protocol (not re-fetched).
5. **Dreem/Beacon timeline citations (row 14).** Two of the four facts are attributed to articles that do not contain them; the report must cite Sleepopolis (March 2021) and beacon.bio/waveband or MassDevice (Waveband) instead.
6. **LucidScribe "plugin descriptions" (master table).** The quoted phrase "triggers audio tracks when rapid eye movement patterns are detected" is the description of the ThinkGear and OpenEEG plugins (28 and 26 stars, pushed 2022-05-01 and 2022-04-25). The Muse plugin's description is only "Monitors the EEG and accelerometer data from InteraXon Muse EEG devices" (9 stars, pushed 2015-05-06); it does not itself claim REM-triggered audio.
7. **Portiloop "comparable to offline experts" (rows 3 and Q5).** Holds for the real-time detect-and-stimulate metric (f1 0.71 vs expert inter-rater 0.72 on MODA); per-sample online detection scored f1 0.61. Quote the metric, not just the adjective.
8. **Hypnodyne ZMax "~89% agreement with human consensus" (Q1, Q3).** The figure on hypnodynecorp.com is an external validation quoted by the vendor (Salfi et al.: accuracy 88.83%±2.84%, Cohen's κ 0.84±0.05), not Hypnodyne's own measurement. The JavaScript quote is "detect REM sleep and play an MP3 sound in response", not "detect REM and play sounds". The page lists MATLAB, Python, PHP, C++, C#, Java and Visual Basic for the TCP socket and gives no price (confirmed); whether autoscoring is paid was not visible in the fetched text.
9. **home-tmr "MIT" and parameter list (row 5).** The license is in the LICENSE file, not the README; ADAPTATION_STEP is only mentioned in the README's notes and PASSIVE is a config keyword, not a parameter. Harmless, but do not present the notes' list as the README's parameter table.
10. **Taran-Douley "0.9% in wake/REM" (row 9).** This is an offline Sleep-EDF simulation with a stage gate derived from PSG-labelled data; the README itself says hardware latency "numbers are assumptions until measured". It is not evidence about Muse S Athena performance.
